# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository.

## Project

Tower Defense: a mobile-first city-defense game in TypeScript + Vite. No backend, no game engine, no framework. Canvas draws the board; the DOM (built as HTML template strings in `src/ui/` and `src/defend/ui.ts`) provides controls, stats, and pages. All state persists in `localStorage` under `towerdefense.v1`. Deployed to GitHub Pages at `https://sethrimer3.github.io/TowerDefense/`.

## Commands

Requires Node 22.18+ (CI uses 24). Tests run `.ts` files directly via `node --experimental-transform-types` (no build step; the experimental warning is expected).

```sh
npm run dev            # Vite on 127.0.0.1:5173 (PORT env overrides)
npm run build          # tsc --noEmit && vite build -> dist/
npm test               # all tests/*.test.ts via node:test
node --experimental-transform-types --import ./tests/pin-random.ts --test tests/defend-replay.test.ts                     # one file
node --experimental-transform-types --import ./tests/pin-random.ts --test --test-name-pattern="Smithy" tests/*.test.ts  # one test
npm run test:pointer   # Defend board pointer gestures vs tests/fixtures/defend-pointer.golden.json (needs `npm run dev` running)
npm run test:performance # Browser crowd benchmark, 500 through 10,000 enemies (needs dev server)
npm run test:stress      # Tower/units/effects stress scene; Chrome profiles and JSON (needs dev server)
npm run test:stress-ui   # Full battle page, HUD and frame overlay (needs dev server)
npm run test:render-cache # Original-vs-cached pixels, invalidation and memory bounds (needs dev server)
node tests/defend-controls.mjs # Header placement, speed persistence and compact explicit-close defeat reports (needs dev server)
node tests/defend-small-boats.mjs # Compact boats, visual water and heading sprites (needs dev server)
node tests/defend-small-fortress.mjs # Compact walkers, damage states and body cache dimensions (needs dev server)
node tests/library-idle.mjs # Library/Mine catch-up, fire pixels and mobile countdowns (needs dev server)
node tests/card-upgrades.mjs # Individual Study cards, spreading, mixed builds, evolution, reload and mobile fit
node tests/upgrade-work.mjs # Timed Study/Forge purchases, shared staff, refunds, reload completion and mobile fit
node tests/library-navigation.mjs # Whole-room Lab/Nave framing, Mine building picker and research/back transitions (needs dev server)
node --experimental-transform-types --import ./tests/pin-random.ts tools/measure-upgrade-production.ts # Bounded 1x Mine/Library scenarios, no player saves
node --experimental-transform-types --import ./tests/pin-random.ts tools/estimate-upgrades.ts # Catalog costs, rank CSV and docs/UPGRADE_TIMING.md (uses measured JSON)
npm run font           # Rebuild the Alembic pixel font from scripts/pixel-font/glyphs.txt
```

- Every Node test process preloads `tests/pin-random.ts`, which swaps `Math.random` for a fixed-seed stream before any module loads and pins the random streams' start-up seeds by name (`globalThis.__pinnedSeeds`, read by `src/random.ts` and `src/defend/grid.ts`), so a failure always reproduces. Run single files with the same `--import`. `tests/test-size.ts` (`FULL`, `ciOnly`) sizes slow property checks: CI sets `CI` and runs them in full.
- `test:pointer` defaults to installed Microsoft Edge (the stress and render-cache scripts to installed Chrome); set `PLAYWRIGHT_CHANNEL=chrome`, or `PLAYWRIGHT_EXECUTABLE=/path/to/chrome` (in the cloud container: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`), which every browser script accepts. It hits the dev server at `http://127.0.0.1:5173/` (or `TEST_URL`) and seeds state by writing the `towerdefense.v1` save into localStorage. Its hashes depend on the page layout and machine: when a change moves the page, record it with `UPDATE_GOLDEN=1` on the unchanged code first, then compare. Output goes to `test-results/` (git-ignored).
- Source imports use explicit `.ts` extensions (`allowImportingTsExtensions`), required so Node can run them directly. Keep this in new imports.
- `tsconfig` only includes `src/`; tests are not type-checked by `npm run build`.
- CI (`.github/workflows/static.yml`) runs `npm test` and `npm run build` on push to `main`, then deploys `dist/` to GitHub Pages (the repository's Pages source must be **GitHub Actions**). Vite `base: "./"` keeps asset paths relative, so the build works under `/TowerDefense/`; asset URLs must not be root-absolute.

## Architecture

**Metal economy.** `src/metals.ts` shares prices, affordability, payment and Copper/Silver/Gold labels; `save.smithy` is the sole spendable metal wallet. Mine/Library hosts expose `metals` and `spendMetals`. Starting metal is 10 Copper; a second miner costs 2 Copper, the first shelf 1 and the first librarian 2. Mine level upgrades start at 4–6 Copper; later levels add Silver then Gold. Larger crews/collections add precious metals, and lab expansions start at 10 Copper before adding Silver/Gold. Bombs cost 1 Copper (`BOMB_PRICE`). Unlimited money bypasses affordability and spends nothing. DEFEND awards only one upgrade point per new highest wave; `payWave` records the best with payment so duplicate events cannot pay twice. Knowledge comes only from the Library. There is no battle Gold, Gold found, Plunder, Copperworks or Spoils topic. Run `tests/metals.test.ts`, `tests/progression.test.ts`, `tests/tiles.test.ts` and `node tests/metal-economy.mjs` (isolated desktop/mobile browser fixture).

**Quadratic balance and project work.** `src/economy.ts` holds price coefficients, used by Training, Forge, Mine buildings/hires and Library shelves/staff/lab. Training costs `1 + 5 * owned²` of its metal tier and takes `60 * next-rank²` seconds per smith. `src/forge-jobs.ts` reserves mixed metals for all ordinary upgrades and War drums, taking `120 * next-rank²` seconds per smith; its one project shares named smiths with Training via `busySmiths`. `src/research-jobs.ts` reserves Knowledge for every skill, path rank and evolution, sharing all current researchers on one lab project: `300 * next-rank²` researcher-seconds or 24 researcher-hours for a crown. Zero workers pauses; completion applies effects exactly once; cancellation refunds the saved actual paid bill, including across dev toggles. `save.researchJob/researchClock` and `save.forgeJob/forgeClock` persist work; Training jobs retain `paid`. Main settles all clocks each second and after loading. Study/Smithy show time, staffing and refund controls. Instantaneous research covers both rooms. Run `tests/upgrade-work.test.ts` and `node tests/upgrade-work.mjs`.

**Water and winter ice.** `boats.ts` indexes all pools, filtering decorative or frozen pools out of liquid combat checks. In cold areas (or debug snow), water freezes at its current radius and every boat leaves persistent frozen sheets, including small boats. Quantized, deduplicated winter emissions bound stationary trails. Fireballs, burning ground, wizard flames, dragon breath and explosions thaw intersecting sheets into water with a fresh eight-second lifetime; melted sheets never refreeze. Ice survives later area changes for the rest of the battle. `icyCell` blocks builder jobs and final rebuilding wherever ice overlaps rubble. `ice-motion.ts` retains ground-unit momentum, adds blast impulses on ice, and checks collisions along slides. Fliers and boats do not slide. Natural ponds freeze during cold weather and heat opens liquid cells (`thawedPonds`); their permanent pond water remains. Surfaces are transient battle state, not saved. `flood-art.ts` draws softer banks, separate reflections for disconnected spans, tree reflections, bounded movement wakes and rain rings; ice has fixed facets and cracks. `pond-water.ts` adds footstep rings and frozen pond art. Reduce Motion disables rings and shimmering; disabling park effects still leaves gameplay ice visible. Run `tests/defend-ice.test.ts` and `node tests/defend-water.mjs` (dev server required, desktop/mobile galleries in `test-results/`). Water buffer checks compare reused storage with fresh current art because the visuals intentionally differ from the frozen reference.

**War banner research.** The Skills palette lets the banner be placed immediately, then enforces a battle-time cooldown of 10 seconds (Rapid deployment reduces it to 7, 4 and 1). Its Study topic has shared cooldown, defense (10% less damage received) and influence radius (5 to 7 cells) upgrades before independent damage (+25%), marching speed (+50% while heading toward the banner) and life (+25% within influence, preserving health percentage on transitions) branches, with regeneration (5% of influenced maximum HP per second) after life. Existing War banner research remains a permanent troop damage bonus. `war-banner.ts` owns influence and health transitions; defender damage routes through `hurtDefender`. Research ranks use the existing skill save decoder. Placement ghosts and planted circles share the researched radius. Skills show a battle-time dark cooldown fill and gold ready outline. Run `tests/defend-war-banner.test.ts` and `node tests/defend-war-banner.mjs` (dev server required, isolated saves).

**Defend controls.** Build/Skills and Tiles/Abandon sit at the left; Start Defense or the keep-health/wave box is centered; starting wave/battle speed sits before the journal and settings at the right. The starting-wave button reuses its zone's wall art under a dark filter. `DefendSave.battleSpeed` persists the chosen 1�/2�/unlocked 3� speed and is restored on each run; legacy or invalid values default to 1�. The enemy journal groups discovered species into each eligible zone, including offspring, sorted by difficulty. Defeat reports close only via their X or bottom Close button, with compact charts and a fixed footer.

**Defend areas.** `src/defend/areas.ts` defines ten destinations, twenty waves each, repeating after wave 200: Mossbound Ruins, Amber Desert, Ember Forge, Drowned Temple, Fungal Hollow, Frozen Vault, Violet Geode, Obsidian Crypt, Astral Sanctuary, Nadir. Mossbound Ruins keeps the original green art. Selected starting waves preview their own area; the renderer crossfades cached city layers over three seconds at an area boundary, keeping live damage and rebuilding consistent in both layers. Reduce Motion snaps the transition and suppresses precipitation animation. `city-layer.ts` loads four floor tiles per area from `public/assets/defend/areas/` (their baked lighting evened out and each framed as a slab by `tools/even-area-floors.py`, run once after cropping). Every area after Mossbound Ruins draws its wall as pixel art from `area-wall-art.ts` (`wallCapSprite`, `wallFaceSprite`: 16 art pixels a cell, each cell a dressed cap stone, whole or split, lit from the upper left, with the area's dressing: sandstone strata and drifts, glowing basalt joints, weed and barnacles, mushrooms, snow and icicles, amethyst, glassy obsidian, gilded star stone, the void's runes) and its fallen stones in the area's tones (`wallRubbleTones`); standing-wall geometry still owns joins, breaches, outlines and the hanging south face. `tests/defend-area-walls.test.ts` checks the art is opaque, distinct per area and stable. `GroundRelief` invalidates by area as well as scale and loaded art. `weather.ts` rolls on entering an area: moss has 30% rain, Drowned Temple 75%, Frozen Vault snow (a blizzard on a `STORM_CHANCE` roll or at night, drawn under the units), Amber Desert a sandstorm, Fungal Hollow mist, and other dry/underground areas no rain. `atmosphere.ts` (`Atmosphere`, `sim.atmosphere`, null outside those two areas) steps mist and sand per cell at 10 Hz on a wrapping board: wind (`windAt`) eases between held headings, blasts and projectiles swirl it (`disturb`, `wake`), mist seeps through walls below 75% HP, sand only through breaches, walkers push dunes, and city sand past `CLEANUP_DEPTH` is the civilians' lowest-priority job (`jobKind: "sand"`); leaving the desert clears it. `atmosphere-art.ts` paints dunes and mist as dithered pixel art at four pixels a cell, plus grains and outlined tumbleweed sprites (`tumbleweedPixels`); `tests/defend-atmosphere.test.ts`. `wave-picker.ts` groups and colors waves by area. `area-enemies.ts` restricts wave selection to themed rosters; Nadir permits every non-hatched species. Offspring remain parent-only, budgets and multipart caps still apply. Nadir reuses crypt textures under a dark violet floor wash. Frozen Vault includes ships plus Ice Golems (double fire/explosion damage via the explicit damage element) and Sliding Ice Cubes (`ice-enemies.ts`: cardinal slides, bounded persistent trails, no blast deflection). `ice-enemy-art.ts` caches native pixel sprites; journal, kill accounting and discovery cover both. Run `tests/defend-zone-enemies.test.ts` and `node tests/defend-ice-enemies.mjs` for behavior and the isolated art/trail gallery. `tests/defend-areas.test.ts` checks boundaries, weather, fades and assets; run `node tests/defend-areas.mjs` with a dev server (optional `TEST_URL` and browser environment variables) to check browser pixels, mobile controls and direct starts using isolated fixtures without player-save access. `tools/prepare-area-art.ps1` crops supplied floors.

**Walking fortress enemies.** `catalog.ts` includes Walking Watchpost (5 difficulty), Walking Outpost (10), Walking Fortlet (50), and Walking Stronghold (100) below the existing Bastion tiers. They share `fortress.ts` armor protection, leg slowdown and independent turrets, with smaller bodies, part HP and `partScale` hitboxes/art. Single turrets are centered; `fortress-art.ts` draws native compact courtyard sprites and keys body caches by dimensions as well as look. Wave budgets reserve every part; only the core counts as a kill. `tests/defend-fortress.test.ts` covers these variants, their journal persistence and art.

**Small magic boats.** `catalog.ts` adds Runed Dinghy (5 difficulty), Charmbound Sailboat (10), Mystic Cutter (50), and Arcane Cog (100), with smaller hulls using the larger boats' palettes. Their `BoatDef.decorativeWater` marks emitted `Flood.decorative` pools; `boats.ts` omits liquid decorative pools from wetness and sinking checks; their winter ice follows the shared ice rules. They still ram solid buildings and the keep, but their wakes neither damage mages nor alter fire, splash damage or shelter. `FloodArt` draws and dries both pool kinds. `tests/defend-boats.test.ts` covers harmless wakes, overlaps, ramming, kill accounting and journal persistence; `node tests/defend-small-boats.mjs` checks browser hulls and water using an isolated fixture.

**Defender targeting and transient buffers.** `defender-index.ts` buckets friendly units in four-cell bins only during the enemy phase, with live HP checks and original array-order tie breaking; small crowds and out-of-phase calls keep the linear scan. Rebuild before each indexed enemy phase, and end indexing before recruitment or friendly movement. Health-bar selection keeps an ordered top eight and only tracks peak strength when bars are hidden. `FloodArt` writes directly into reusable ImageData backing arrays, growing capacity at most to board size. `tests/defend-query-performance.ts` runs paired targeting/health-bar microbenchmarks; defender-index tests compare against the original scan, and render-cache tests compare original water pixels across pool resizing and settings.

**Lightning rasterization.** `BoltBuffer` in `src/defend/dark-art.ts` keeps a bounded typed array of occupied pixel indices, clearing and colouring only those pixels rather than scanning the rectangle between distant bolts. Overlapping marks retain their existing priority. Dirty upload bounds remain unchanged. `test:render-cache` compares the buffer against the frozen original across overlaps, 250-link chains, clipping, fading and clearing, and reports a sparse lightning microbenchmark.

**Light field.** `DefendLighting.drawLight` no longer draws each light's two swayed bakes scaled up onto the board-sized darkness and glow (four filtered draws a light, a frame). `LightField` (`src/defend/light-field.ts`, pure typed arrays) sums them on the bakes' own lattice (`RES` samples a cell, `FIELD_W` × `FIELD_H`): each bake carves `1 - alpha × level` from the darkness and adds its premultiplied candle colour to the glow, the flame's sub-pixel bob resampled between rows; the result is painted to two field-sized canvases and drawn up to the board once each. A glow past full is painted at a half or a quarter and added onto itself after drawing up (`paintGlow`'s doublings), so saturated pools still spread full brightness into their edge pixels. Hand torches are summed on their own field layer (a 1024-step falloff table) and drawn up, then kept to open ground by the full-resolution ground mask as before. It is close to the old drawing, not exact: where pools meet a wall's edge they are multiplied before they are smoothed, so those edge pixels differ by up to about 30 of 255 (mean about 1). `tests/defend-light-field.test.ts` checks the arithmetic; `test:render-cache` compares against the frozen original lighting with that tolerance and checks the trees' shading box exactly. `ParkTrees` clears, shades (`source-atop`, clipped) and copies back only the box round the trees.

**Battle frame timings.** `defendFrameTimes(true)` enables the optional `FrameTimeOverlay` (`src/defend/performance.ts`), with update, entities, effects, terrain and UI means plus frame p95; it changes the DOM at most twice a second and resets when Defend is hidden. `DrawOptions.timings` enables render-pass timing. Terrain includes city-layer refresh and drawing (parks and flood water too); effects is the remaining draw time, including lighting. `GroundRelief` retains exact eight-pass masks in a 256-entry / 32 MiB RGBA-pixel LRU (mask/fixed canvases are additional), reusing brightness-independent sprites and evicted canvases. Its masks invalidate on map identity, scale or loaded floor art. Mage scorch sprites are recyclable per-blaze WeakMap entries at their existing eight-Hz pulse; flame tongues stay live. Combat pixels are cached at screen resolution between fixed simulation ticks, keyed by simulation, time, map version, effect/scorch/unit counts, camera, dimensions, torch and health-bar settings; wall-clock chill glints stay live and the cache is bypassed during torch dousing. Tiny ice/explosion sprites use software-backed baking (`pixel-fx.ts`). `tests/defend-stress-scene.ts` provides a deterministic mixed combat fixture, used by the isolated renderer benchmark and `/tests/defend-stress.html` (no player-save access). `PERF_MIX=heavy` adds a siege-heavy variant; `PERF_REFERENCE=1` uses frozen original rendering modules, content-addressed to avoid Vite's ignored-file cache, and `PERF_VARIANT=relief|scorch|combat` isolates successive fixes (`light` is everything current; `PERF_REF` picks the frozen revision, `3f71ff2` for the light field's before). See `docs/DEFEND_FRAME_TIMES.md` for measurements, limitations and commands.

**Performance experiment.** Defend waves currently contain exactly `500 * wave` enemies (bosses included, hatched brood extra), released over five seconds. `src/defend/performance.ts` logs per-wave FPS, frame p95, update/draw timings and peak enemies every five seconds and on completion/loss/abandon; the latest 100 rows are available at `window.defendPerformance`. Timings are presentation-only and not saved. Dense crowd separation samples at most 8 enemies per indexed cell deterministically, with exact separation in sparse cells. Grass indexes only cells with blades; large-crowd shadows are cached between simulation ticks at unzoomed scale and invalidated when lighting changes; same-pixel shadows of matching size and light are coalesced at this scale. `tests/defend-performance.mjs` benchmarks spawn and city crowds using the full renderer (rain, night, effects on), isolated from player saves. `PERF_SCENE=city`, `PERF_WAVE=20`, `PERF_REALTIME=1`, `PERF_LABEL=name` `PERF_MIX=1` and `PERF_PROFILE=1` select scene, count, wall-clock stepping, output name, mixed enemy kinds and CPU profiling. `PERF_FRAMES` sets the sample length (default 150 frames, first 30 warm up). Defaults run all 20 counts with a fixed 1/60-second update per frame for comparable work; real-time mode is necessary to assess actual pacing. JSON, screenshot and optional CPU profile go to ignored `test-results/`. Replay fixtures include explicit mixed sieges and a quiet repair interval so the stress opening does not remove late-enemy/repair coverage.

**Shell.** `main.ts` builds the shell (`ui/shell.ts`: the currency bar of the Mine's Copper, Silver and Gold (`save.smithy`, the Gold ingot is labeled GOLD), Knowledge and upgrade points, with a locked slot kept for a resource still to come, all on one line at any width, counts from 10,000 shortened to 12.4k, 1.2M (`compact` in `main.ts`, the exact count in the tooltip), the pages and the tab row: Defend, Mine, Library, Tiles, Settings; the Mine's and the Library's pages are `descentHtml` skeletons, the tab's scene over the earth and the room below it), loads the save, owns the current tab and `navigate()`, runs the requestAnimationFrame loop (the Mine's and the Library's work on every tab, Defend's and the Mine's frames (a scene only while it is in view), the rooms below the Mine and the Library and the Tiles tab's hall, and a once-a-second tick that settles Training and Forge against the mine's smiths, and Study against the Library's researchers), and passes pages an `AppContext` (`ui/app.ts`). It also creates the `DefendPage` with its `DefendHost`: the Defend save slice, `bonuses()`, and `openTiles` (the header's Tiles button, where the Armory used to be), and `earnWave`, which awards upgrade points through `progression.ts`. The Settings page (`ui/settings-page.ts`, rows in `SETTINGS`) opens with a Gameplay group (Show items you have none of, `showEmpty`: off by default, so the Defend palette lists only items with copies left, the host's `showEmpty`) and shows the Tile grid lines toggle's opacity slider only while it is on. Its dev options sit under ALL ON: Unlimited money (`devMode`: ∞ everywhere, every purchase free), All towers unlocked (`devTowers`: `unlockAllTowers` gives one of every structure when turned on), Instantaneous research (`instantResearch`: any Smithy or Study project completes at once, worker or none) and All research unlocked, one per tree (`devSmithy`, `devCommand`, `devStewardship`, `devMine`, `devLibrary`, `DEV_RESEARCH`: while on, `skillRank`/`trainingRank` count every rank of it as bought; the save's ranks are untouched). Add 1 hour of idle time (`addIdle`) gives the Mine (`MinePage.addAway`: tick-by-tick catch-up, up to 24 hours banked) and the Library (`LibraryPage.addAway`: ordinary simulation steps spending the same idle-time bank) that time, moves all active project clocks back, and shows the welcome-back screen with what it made. Unlock 100 more waves (`unlockWaves` in `defend/progress.ts`) raises the Defend save's `unlockedWave` to 100 past the furthest of it and the best wave. `defendDebug(seconds, weather?)` in the console fast-forwards a battle, `mineDebug(minutes, hire?, weather?)` the mine (forcing the weather), `mineLevel(id, level?)` sets a mine building's level (or, with none, upgrades it for free, rebuild and all), `mineLook(building, zoom?)` zooms in on a mine building and picks it, `libraryDebug(shelves, librarians, seconds, fire?)` furnishes and runs the library (and sets a table alight), `libraryLab(level?)` raises the alchemy lab for free and fills it with researchers, and `libraryEnchant(n?)` enchants that many shelved books. While the Mine and the Library spend idle time, a golden countdown (`.tab-idle`, `idleTimers` in `main.ts`) sits at the top of their tab buttons, hidden on the tab showing; the two spend it together, neither more than `IDLE_LEAD` (`src/away.ts`) ahead of the other (each `advance` takes the other's `owedMs`), and both buttons show the longer.

**Library** is a cathedral nave the player fills, in `src/library/`, saved as `save.library` (null until it first shows); it earns Knowledge, `knowledgeRate` = built shelves × professors an hour. `geometry.ts` holds where things stand, in pixels (192 × 300, the floor's top at `FLOOR`; a hallway `HALL` long out of each side wall, with `EXITS` at their ends and a water butt in each, `BUTTS`; the return shelf, `RETURN`, holding `RETURN_BOOKS`; and below the nave the alchemy lab, `LAB_TOP` to `LAB_FLOOR`, the picture `WORLD_H` tall, its ladder down from a trapdoor at `STAIR_X` and its stations in `LAB`). `sim.ts` (`LibrarySim`): each shelf unit (two rows of seven books) has a plank count in `units` (-1 none, 0 an outline once bought, `PLANKS` built); units stack in ten bays against the back wall in `SHELF_ORDER` up to `SHELF_TOP`, under the stained-glass `WINDOW`. Librarians (2 × 4 pixels, each with a hat and robe of their role) have a name for life (`librarianName`) and a `role` (`ROLES`): a hire takes `roleFor`'s pick (the first a professor, the second a shelver, the third a researcher, then whichever of shelving and reading has fewer) and the player changes it in the tab's Staff list (`setRole`, which drops what they were doing). Shelvers (and professors while there are no shelvers, `shelving`) do the stacks' work below; professors (`readJob`) take a fresh book down, read it at a table seat (`study`) or standing, and put it, read (`spent`, counted in `read`), on the return shelf (`returns`, `returnJob`); every book on the shelves is unread. Researchers climb down to the lab, where `lab.ts` (`labErrand`) gives them errands station to station (an ingredient from the jars poured into the cauldron and stirred, the athanor's bellows, the alembic, whose full receiver feeds the philosopher's stone, the desk, the mortar, a chant at the circle, the homunculus) over the apparatus's state (`LabState`, `sim.lab`: furnace, brew, still, stone, glow, puffs, busy stations; `stepLab`), now and then a brew going up in smoke and leaving its brewer sooty (`soot`) and a `mess` someone sweeps up, tastings (floating, hiccups), scrolls, feeding the homunculus and conferring at the desk; `researched()` flares the circle when a research is bought. The lab has a level (`sim.labLevel`, 1 to `LAB_MAX_LEVEL`, raised with metal at `labPrice` by `upgradeLab`) and room for one researcher a level (`researcherCap`, kept by `hire`, `setRole` and `roleFor`'s `room`); levels open `ANNEXES` west and east under the hallways, whose stations (`LAB_NEEDS`, `hasStation`) add errands: the mandrake garden (a pulled one shrieks, `shriek`), the lectern, the crucible casting gold (`cast`, `casts`), the orrery (`orrery`), the salamander (`breath`) and the orb (`orb`). They follow step lists (walk, climb, timed work, `away` beyond a hallway's end): one fetches the wheelbarrow of planks (`barrow`) when building wants planks, and the rest carry planks from it to ladders (one segment a plank, up to the built shelves), outlines and burnt tables; another wheels in the book cart (`bookCart`) of new books when shelves stand empty, which the rest shelve; when the return shelf is getting full (or the cart goes for new books anyway) one loads its books into the cart (`exportJob`) and wheels them out, bringing back fresh ones for the gaps (`booksIn`/`booksOut`); otherwise they sort the stacks (each colour has its bay, `homeBay`, and books are shelved there where there is room; `sorted`) or tidy books between bays. Each librarian has `energy`, drained by work (`TIRING`) and restored by a cup of tea fetched from outside or, at night, a doze in a free seat; by night (`night`, which the page sets from `daylight`) about half the shelvers and professors go home down a hallway (`home`) and return by day, researchers working on; now and then two stop to talk (`with`) or one gazes up at the window. After a death the others mourn at the ashes (`remains`), then one sweeps them up and scrubs low soot off the stone (`Fire.scrub`). The two water butts hold `BUTT_FULL` buckets: fire fighters draw from them (and run out to the well when both are dry), those who fled refill them during a fire, and one refills them afterwards. Every book is in a slot, a hand, on a table or in the cart. With the Enchanted ink skill (`enchant`, its ranks), each shelved book has `enchantChance` (1 in `ENCHANT_ODDS`, 10,000, a rank) a minute of becoming enchanted (`sim.enchanted`, a flag per slot that travels with the book in hand, `rune`); a professor reading one gets `enchantedGift` (one minute of the base rate, at least 1) Knowledge at once (`takeBonus`, which the page pays; `runesRead` counts it), and the renderer draws runes glowing up its spine (`drawRunes`). Once a minute a whole table catches fire with `accidentChance(fireproof)` (1% × 0.9 a rank of Fireproof Wood); `fire.ts` (`Fire`) simulates it on a 2-pixel grid of heat and fuel (rising heat, wet cells, thrown droplets that douse with `fireDrill(fireTraining).douse`). Librarians in the nave notice it after a moment, then flee down a hallway or (all shelvers, plus a trained share of professors shelving) fetch buckets from the butts and throw them; heat kills (`deaths`, `remains`); the lab is out of its reach, and the return shelf burns with its books. Fuel consumption removes individual artwork pixels. Smoke rises through empty cells and ash falls and piles up on the floor. When it is out, `settleFire` retains every purchased shelf and intact book, queues missing planks for repair in place, and leaves charred books for shelvers to carry outside, one a trip, after building and fetching planks so rebuilding never waits on them (`burntSlots`, `burntLoose`, `burntFrom`; a charred book whose shelf has burnt away under it falls to the floor, `dropBurnt`, rather than hang in the air); `lost` says what it cost. Night watch speeds detection and bucket work by 15% per rank during simulated nights. **Mine** is the idle side of the game, in `src/mine/`, saved as `save.mine` (null until it first runs). `world.ts` holds the grid (384 × 480 cells, one material each), the world a seed generates (`generate`, `strata`: sky, grass, dirt with rocks, stone with copper, deeper silver and deeper still gold veins, bedrock) and the falling-sand `World.step`: dirt, grass and spoil fall and slide only onto drops of two or more, so slopes settle one across and two up; rocks drop straight; only awake 16 × 16 chunks are stepped. Gravel and loose dirt (pockets in the stone and dirt) slide on any drop and, like falling rock, crush the ladders and timber they land on; lava pools deep down creep slowly and turn to stone where water meets them. `caves` carves natural caves into the stone after the veins (winding passages and wide caverns, hung with stalactites and grown with stalagmites, kept clear of the shaft and the dirt), and lava keeps away from them. A separate `water` layer (one flag a cell) flows down, spreads level and sinks under falling ground. `buildings.ts` lays out the surface buildings either side of the shaft at their levels (`layout(surface, shaftX, levels)`, 1 to `MAX_LEVEL` each, wider each level: the shaft house, the barracks with a lounge and a bay of bunks a level, the warehouse, the forge with two hands' spots a level and the smithy with an anvil a level, `anvils`), each with spots (bunks, stools, stations) and the scripted path to each from the door (`along`, `pathTicks`): a miner inside a building is out of the grid, its feet left at the door. `sim.ts` (`MineSim`) is the operation: a plan grid marks cells to dig or fit (ladder, rail, torch, lamp, `P_BEAM`; `PLAN_MARKS` bounds the decoded plan); the planner sinks the laddered shaft level by level and drives a tunnel out both sides of each, its track crossing caves on a trestle of beams, with now and then a drift slanting up or down off it behind a few rungs of ladder (`planDrift`: level or slanting, lit, ending in a chamber, stopping short of soil, boulders, loose ground and lava) and, from the second level, a winze laddered down from the level above; a dig that breaks into an unworked cave (`discover`) floods its extent into the plan and plans its work (`planCave`: torches along its floors, the ore on its walls by `markVein`, drifts from its ends and lowest point); each miner (1 × 2 cells) picks the nearest unclaimed job by a breadth-first search over where it can stand (walk, step up two, climb or put up ladders underground, drop), shores loose ground beside its digs with timber, follows ore it bares, carries ore to the yard by the shaft house (and spoil to the heap) or into a level's cart, which rolls to the shaft, where its load waits (`buckets`) for the hoist: one bucket (`hoist`) let down to each load in turn and wound up to tip it in the `yard`. Forge hands carry the yard's ore into the forge (`fetch`, `CARRY` at a time, gold first) while it holds less than `FORGE_CAP`, so a short-handed forge leaves the backlog in the yard. Each miner has a name for life (`names.ts`, `minerName`: hashed from the seed and the hire, unlike the rest of the crew's) and a trade (`job`: mine, forge, smith) the player sets per miner in the crew list (`setJob`; `setJobs` puts counts to the trades, `jobs` counts them; the second hire goes to the forge and the fifth to the smithy while they have nobody): forge hands smelt the ore piles (`ore`, a `Metals` record of copper, silver and gold, as are packs, carts, the yard and the hoist) into bars (`bars`, `ORE_PER_BAR` ore each) and smiths work the bars, every `BARS_PER_POINT` of a metal making a Smithy point of it, each at a station inside (`stepInside`, `craft`; a trade with nobody works at a quarter pace); fittings and shoring use supplies (`kit`) fetched from the warehouse; at night (`night`) all but the night shift (`nightShift`: 20%, plus 5% a rank of the Coffee skill) sleep in their bunks; hungry miners eat in the lounge; the shaft house keeps a share of the runoff out of the shaft (`seal`: 20%, plus 15% a rank of Waterproofing) and its roof, like every building's, takes the lightning. The sky turns through day and night (`daylight`, one day every `DAY_TICKS`) and spells of `weatherOf` the seed (clear, cloudy, rain, storm; `skyAt` eases between them): rain falls as water that soaks into soil, runs down the shaft and floods the workings, where miners bail it (and douse fires) as jobs; in storms lightning strikes (and can set wood alight) and miners at the surface sit it out in the lounge. Hazards (`hazards`, `struckBy`, `survey`, `stepFire`) can kill a miner by crushing, drowning, starving trapped (`fed`, `MEAL_TICKS`), lava, fire or lightning; `kill` spares the last miner, any death within `DEATH_GAP` of the last (a new mine starts with that grace) and a second death in one catch-up, records the cause in `lost` and the miner in `fallen` (until the player taps it away, `dismiss`, or hires again), and posts `news` the page and renderer show. A prospect's ore is finite (`oreFound`, `oreLeft` as of the last `survey`): once the shaft is at the deepest level and the planned work is done (or has stopped shrinking for five minutes) it is `workedOut`, and `prospectNext(seed)` builds the next prospect, a fresh world, carrying the crew, the stock and the losses (a `MineSave` without `cells` is such a prospect: the crew starts at the barracks). Each building has a level (`buildingLevels`, raised with metal by `upgrade(id)` at `upgradeCost`, refused by `upgradeBlock`): the barracks bunks `CREW_PER_LEVEL` a level (`crewCap`, which `hire` keeps to), the forge has room for `FORGE_PER_LEVEL` hands and the smithy for `SMITHS_PER_LEVEL` smiths (`jobCap`, which `setJob`/`setJobs` keep to; the forge also holds more ore, `forgeCap`), the shaft house keeps out more rain, and the warehouse holds `STOCK_PER_LEVEL` supplies and brings in `STOCK_RATE` a minute a level (`stock`, `stockCap`, `stockRate`) and lets the others rise one level past it (`maxLevel`). Miners fetch their kit from `stock`, so with none the fittings (and the shaft) wait. An upgrade rebuilds the building and moves any it pushes along (`rebuilds`: taken down at `from`, then raised; shut meanwhile, everyone inside sent out, its trade's hands working the face), using supplies as it goes and waiting when there are none; `setLevel` sets a level at once (tests, the console). Fewer miners make the next hire cheaper (`sim.price`). `collect()` hands over the Smithy points made (into `save.smithy`); `hirePrice` prices miners in metal. Sinking the shaft and the ladders a climbing miner puts up use supplies too, so with none the shaft waits. Smiths working a Smithy upgrade can't be dragged out of the smithy (the host's `busySmiths`); Master smith makes room for another (`extraSmiths`). **Saves.** Top-level battle Gold has been removed; legacy coin balances are ignored without conversion. `src/save.ts` loads defensively: `defaults()` defines every field and `decode()` keeps only what is well formed (a newer version starts afresh; Knowledge was once `valor`, a version 1 save's battle copper and silver (once `ironBar` and `steelBar`) join the mine's metal, whose points it multiplies by ten as `BARS_PER_POINT` went from 100 to 10 (`OLD_BARS_PER_POINT` still bounds a saved mine's `worked`); a new game starts with `STARTING_METAL`; a save from before upgrade points gets one for each wave of its best, and a rank in training from before the Smithy counts as done). When adding save state, add it to `defaults()`, the `Save` type and `decode()`. The mine's grid and plan are stored run-length encoded as base64 (`encodeGrid`/`decodeGrid`), as is its water layer (optional, so older saves load dry), and `decodeMineSave` drops a mine unless it is whole (its burning cells, losses, mercy, miners' meals, names, trades and supplies, the allocation, the forge's and smithy's stock (old saves' iron reads as copper), the prospect, the lost, `workedOut`, the building levels, supplies and rebuilds are checked when present, and a mine saved before levels gets levels with room for its crew and trades; a mine saved before the world was widened, 128 cells across, keeps its crew and stock and starts a fresh prospect of its seed); the library's book slots use the same encoding (`decodeLibrarySave`). **Mine tunnels and lighting.** Stone takes 330 ticks (three times rock); `HARD_STONE` at about 30% underground depth takes 990, and `DENSE_STONE` at about 60% takes 2970. Softer seams cross the deeper strata, and ore/caves work in all three. `routeTunnel` minimizes excavation cost within three rows of a level, with seeded bends and at most a one-cell grade; roof pockets vary the clearance. `tunnelRows` drives rail reach, progression and carts, while the renderer connects rails in one-art-pixel increments. Digging beneath rails plans replacement trestles. Miners set `WORK_LAMP` beside dark working faces, replace spent lamps during long jobs, and plan/build lasting `LAMP` lanterns along established track with irregular gaps and a solid ceiling. Work lamps last 90 simulated seconds; torches last a seeded 120-240 seconds, and spent torch plans become plain dig marks. Lighting checks flood through open cells, so a lamp behind a wall does not suppress a work light. Torches are the right two pixels of a cell (1x2 art pixels); lanterns have a one-pixel-wide ceiling chain and a bottom flame. Carts are three art-pixel rows tall, including their load, with no visible wheels; metal and ore sample the cave's local daylight and warm lighting per pixel. Saves retain remaining light lifetimes (`lights`), compressed floor offsets (`routes`), cart elevations and `geology: 1`; older routes are reconstructed from rail plans, and older prospects upgrade only untouched deep stone, preserving their excavated passages, ore and fittings. Run `tests/mine-tunnels.test.ts` and `node tests/mine-tunnels.mjs` (dev server required; desktop/mobile galleries in `test-results/`, no player-save access).

## Conventions

- Upgrade timing analysis: `tools/measure-upgrade-production.ts` writes `docs/upgrade-production.json` from six preset scenarios (three setups, two seeds), with `ESTIMATE_HOURS` (default 6) and `ESTIMATE_CPU_SECONDS` (default 30 per Mine). `tools/estimate-upgrades.ts` reads those samples and current catalogs, writes `docs/upgrade-estimates.csv` and `docs/UPGRADE_TIMING.md`, and separates exact Smithy/lab work from resource scenarios. `tools/plan-upgrade-progression.ts` conserves shared income across paid infrastructure phases before estimating focused endgame targets. No tool reads player saves; replacement costs, construction downtime, offline distributions and manual requeue delays remain explicit limitations.
- Keep this file current. When a change adds, renames, or removes modules, alters architecture, changes commands/scripts or test setup, or changes save rules, update AGENTS.md in the same change, and keep the README's "How it's built" accurate. `CLAUDE.md` only imports this file; don't add content there.
- `CONTEXT.md` is the domain glossary (terms only, no implementation). Use its words in code, comments and docs, and add a term there when a change names a new domain concept.
- All text uses a bundled font, no remote fonts: Alembic, the game's own pixel font (`assets/fonts/Alembic/`, regular and bold), while the Use Custom Font setting (`pixelFont`, on by default, the root's `.pixel-font` class) is on, otherwise Cinzel (`assets/fonts/Cinzel/`). CSS sets text in `var(--font)`, never a font by name. Alembic's glyphs are pixel rows in `scripts/pixel-font/glyphs.txt`; `npm run font` rebuilds the files (`scripts/pixel-font/build.ts` traces each glyph's pixels into TrueType outlines; the bold thickens each stroke a pixel), and `tests/pixel-font.test.ts` fails until the committed files match. Draw a glyph there when text needs a character it lacks.
- The page's look lives in `src/theme.css`, loaded after `src/style.css` (layout): dressed stone for the hall and tabs, oak boards nailed at the corners for buttons and panels, brass trim and an ember glow for chosen and leading buttons, red lacquer for danger, parchment for dialogs, banners, the Defend settings and tooltips, and an alchemical circle behind the skill trees. Its textures are small tiling SVGs in `assets/theme/` (`stone`, `wood`, `parchment`, `sigil`, `rule`, `seal`, and `frame`, the board's iron corner brackets). Style new UI from its tokens (`--wood`, `--stone`, `--parchment`, `--nails`, `--brass-nails`, `--ink`) rather than flat colours.
- Goldens (`tests/fixtures/*.golden.json`) pin current output; an intended change to city generation, the battle, fences or saves fails them until re-recorded with `UPDATE_GOLDEN=1`. Re-record as part of that change and say which and why in the commit message. A refactor re-records nothing.
- Run the area's tests while iterating (`tests/defend*.test.ts` for Defend, `tests/mine.test.ts` for the Mine, `tests/library.test.ts` for the Library, `tests/progression.test.ts tests/settings.test.ts` for progression and saves), then `npm test` and `npm run build` before committing.
