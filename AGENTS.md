# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository.

## Project

Tower Defense: a mobile-first city-defense game in TypeScript + Vite. No backend, no game engine, no framework. Canvas draws the board; the DOM (built as HTML template strings in `src/ui/` and `src/defend/ui.ts`) provides controls, stats, and pages. All state persists in `localStorage` under `towerdefense.v1`. Deployed to GitHub Pages at `https://sethrimer3.github.io/TowerDefense/`.

## Commands

Requires Node 22.18+ (CI uses 24). Tests run `.ts` files directly via `node --experimental-transform-types` (no build step; the experimental warning is expected).

```sh
npm run dev            # Vite on 127.0.0.1:5173 (PORT env overrides)
npm run build          # tsc --noEmit && vite build -> dist/
npm test               # all tests/*.test.ts via node:test
node --experimental-transform-types --import ./tests/pin-random.ts --test tests/defend-replay.test.ts                     # one file
node --experimental-transform-types --import ./tests/pin-random.ts --test --test-name-pattern="Training" tests/*.test.ts  # one test
npm run test:pointer   # Defend board pointer gestures vs tests/fixtures/defend-pointer.golden.json (needs `npm run dev` running)
```

- Every Node test process preloads `tests/pin-random.ts`, which swaps `Math.random` for a fixed-seed stream before any module loads and pins the random streams' start-up seeds by name (`globalThis.__pinnedSeeds`, read by `src/random.ts` and `src/defend/grid.ts`), so a failure always reproduces. Run single files with the same `--import`. `tests/test-size.ts` (`FULL`, `ciOnly`) sizes slow property checks: CI sets `CI` and runs them in full.
- `test:pointer` defaults to installed Microsoft Edge; set `PLAYWRIGHT_CHANNEL=chrome`, or `PLAYWRIGHT_EXECUTABLE=/path/to/chrome` (in the cloud container: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`). It hits the dev server at `http://127.0.0.1:5173/` (or `TEST_URL`) and seeds state by writing the `towerdefense.v1` save into localStorage. Its hashes depend on the page layout and machine: when a change moves the page, record it with `UPDATE_GOLDEN=1` on the unchanged code first, then compare. Output goes to `test-results/` (git-ignored).
- Source imports use explicit `.ts` extensions (`allowImportingTsExtensions`), required so Node can run them directly. Keep this in new imports.
- `tsconfig` only includes `src/`; tests are not type-checked by `npm run build`.
- CI (`.github/workflows/static.yml`) runs `npm test` and `npm run build` on push to `main`, then deploys `dist/` to GitHub Pages (the repository's Pages source must be **GitHub Actions**). Vite `base: "./"` keeps asset paths relative, so the build works under `/TowerDefense/`; asset URLs must not be root-absolute.

## Architecture

**Shell.** `main.ts` builds the shell (`ui/shell.ts`: the currency bar of Gold, iron, steel, Valor and the Commander level with its experience bar, three pages and the tab row), loads the save, owns the current tab and `navigate()`, runs the requestAnimationFrame loop (Defend's frame, the Upgrades page's particles, and a once-a-second tick that settles Training), and passes pages an `AppContext` (`ui/app.ts`). It also creates the `DefendPage` with its `DefendHost`: the Defend save slice, the wallet (Gold and bars; Dev mode and free purchases spend nothing), `bonuses()`, and `earnKills`/`earnWave`, which pay through `progression.ts`. `defendDebug(seconds, weather?)` in the console fast-forwards a battle.

**Defend** is the game, self-contained in `src/defend/` with its own save slice (`save.defend`) and page (`DefendPage`, `defend/ui.ts`); see `docs/DEFEND.md`. Its battle simulation, `DefendSim` (`defend/sim.ts`), owns the world state and what happens to it (damage, rebuilding, blasts, movement), and steps the units in a fixed order. Each unit type's decisions live in its own module: `enemies.ts`, `troops.ts` (barracks, swordsmen, archers), `civilians.ts`, `towers.ts` and `wizard.ts` (wizard towers alternating `sim.flames` and `sim.frosts`; an enemy's optional `chill` slows it, and stays absent when unset so runs without ice hash exactly as before). `pathing.ts` holds the pure grid A*, the enemies' flow field and the collision test. A sim takes the Armory's levels and, optionally, `Bonuses` (`catalog.ts`: multipliers on troop HP and damage, drill time, tower damage and reload, wall and keep HP, rebuild time and bomb damage; `NO_BONUSES` is all 1, so a sim without them plays exactly as before), and counts the enemies slain by kind (`sim.slain`, which the page pays for each frame; not part of the replayed state). `DefendRenderer` (`defend/render.ts`) owns the camera and the order of the drawing passes: `city-layer.ts` paints the cached static city (it re-exports the pond and tree geometry of `park-geometry.ts`, `pondDisc`/`pondPath`/`POND`, `hasTree`/`treeCanopy`, that the live effects line up with), then **park life** over it (`park-art.ts`, `parkArt`: the ponds and trees as pixel art at 8 pixels a cell, baked once per city with the open-water mask everything on the water keeps to, its geometry from `park-geometry.ts`; `pond-water.ts`, `PondWater`: faint pixel rain rings all over the water while it rains, and the bank mirrored into the water from the city layer in strips shifted by the shimmer and the rings, tinted and masked to the open water; `pond-ducks.ts`, `Ducks`: a few pixel ducks when it isn't raining, with drift, paddle, dabble, preen, follow, flee and sleep states and rare wake rings; `park-grass.ts`, `ParkGrass`: blades planned per park cell clear of canopies and shores, swaying with the wind and gusts, parting around the walkers the renderer passes, written into one pixel buffer at 8 pixels a cell and rebuilt at most 30 times a second; both skipped when the `effectsOff` setting is on), `fences.ts`, `lighting.ts` the torchlight and shadows, `ground-relief.ts` (`GroundRelief`: the flagstones' bump map outside the city, four facing masks baked from the floor art's brightness by `paintFloor` in `city-layer.ts`, lit per light through cached weight sprites; fixed lights baked per map version, moving ones per frame), `battle-art.ts` each frame's damage, scorches, units and effects, `wizard-art.ts` (`WizardArt`: the wizard towers' fire particles and the ice wave's shaded crystal shards, advanced on battle time; `flameLights` turns each flame into carried and relief lights), `edit-overlay.ts` the building grid and drag overlay, and `structure-art.ts` the building art, banner and palette icons. Park life is presentation only: it never changes the city or the battle, and draws its randomness (rain rings) from `defendRandom("effects")`. All units draw from one seeded random stream, so the step order and each unit's draws decide a replay. `tests/defend-replay.test.ts` steps fixed cities, upgrade levels, seeds, bombs and demolitions through `update()` and hashes the whole sim state every 5 s against `tests/fixtures/defend-replay.golden.json`, reporting when a run first diverges. Regenerate it with `UPDATE_GOLDEN=1` only for an intended gameplay change. The battle must play the same in every JavaScript engine and Node version (CI runs Node 24), so battle code uses only `+ - * /` and `Math.sqrt`, with `intPow`, `sq` and `dist` from `src/exact.ts`: no `Math.pow`/`**`, `hypot`, `exp`, `log` or trigonometry (the wizard aims by unit vectors and tests cones by slope). Drawing may use `Math` freely. Check a replay change under both: `npx -y node@24 --experimental-transform-types --import ./tests/pin-random.ts --test tests/defend-replay.test.ts`. On the page, board pointers go through `board-pointers.ts` (`BoardPointers`), a small state machine: idle, viewing (one pointer pans, two pinch-zoom), or dragging a palette item, structure, keep, city tile or bomb under a ghost icon. It only turns pointers into board cells; each drag is an `EditSession` (`edit-session.ts`), a pure transaction over the layout it started from: what a press lifts (`EditSession.lift`), the legal tiles and the layout each makes, the overlay shown while held, and the `Drop` a release makes, which the page applies. `tests/defend-edit-session.test.ts` drives whole drags in Node. `drag-rules.ts` holds the rules behind it (unit-tested in `tests/defend-drag-rules.test.ts`). The city itself comes from `layout.ts` (the player's tiles and structures; `fitLayout` picks each structure's cells) and `citygen.ts` (streets, parks, houses, ponds and wall stones, as a pipeline of stages). `tests/defend-city.test.ts` hashes seeded random walks of layout edits, their fits and failure reasons, and the cities generated along the way against `tests/fixtures/defend-city.golden.json`; regenerate it with `UPDATE_GOLDEN=1` only for an intended change to city building. `fences.ts` lays decorative fences along the street sides of parks and snaps them into splinters under walking enemies and blasts, and `progress.ts` holds the saved Defend state, its purchases, and `decodeDefendSave`, which rebuilds the saved layout piece by piece and drops it unless it is well formed, owned and still fits. `tests/defend-fences-save.test.ts` hashes fence sections, seeded fence runs and `decodeDefendSave` over a corpus of saves against `tests/fixtures/defend-fences-save.golden.json`. `tests/defend-park-life.test.ts` checks where grass is planned, the pixel ponds' open water, and the ducks keeping to it, fleeing walkers and sleeping at night, and `tests/defend-wizard.test.ts` the wizard tower's turns, cone and chill.

**Progression** (`src/progression.ts`, pure functions over the save): Commander levels from lifetime experience (`xpForLevel`, `levelForXp`), training points (`TRAINING_PER_LEVEL` a level; `trainingPoints` counts ranks owned and in training, less `save.freeTraining`), the `TRAINING` rows (each rank `per` percent on its target, `max` ranks), timed ranks (`startTraining`, `cancelTraining`, `settleTraining`; durations and the base slot count in `training-jobs.ts`: 60 s for a row's first rank, each after 50% longer; `trainingSlots` adds the Tactician skill), the skill trees' purchases (`skillPurchase`, `buySkill`), and what a defense pays (`payKills`: `KILL_GOLD` and `killXp`; `payWave`: `waveGold`, iron, steel on boss waves, Valor past the best wave). `multiplier(save, target)` adds Training's and the skills' percents for a target (a time's percent divides), and `bonuses(save)` folds them into the battle's `Bonuses`; `gold` and `xp` multiply the rewards. `src/skill-trees.ts` defines the skills (`SKILLS`: name, glyph, max ranks, Valor `base` with `skillCost = base × (rank + 1)`, effect) and the two `TREES` (Command, Stewardship) with node positions and requirements; `ui/skill-tree-page.ts` (`SkillTreePage`) draws Training and the trees (pan and zoom with `ui/pan-zoom.ts`, particles from `tree-particles.ts` and `training-particles.ts`). `tests/progression.test.ts` covers it.

**Torch light toolkit.** `src/lighting.ts` (the candle colour ramp, flicker and sway: `getTorchFlicker`, `getTorchSway`, `LIGHTING_CONFIG`), `src/torch-light.ts` (`lightFalloff`, `glowColor`, and the occlusion-aware baked glow `torchLightField`/`bakeTorchLight`) and `src/visibility.ts` (`Torch`, `TORCH_LIGHT`, `computeVisibilityPolygon`, `insidePolygon`) are kept from the dungeon game for Defend and future use; `defend/lighting.ts` builds the city's lights on them.

**Randomness.** Defend's city, battle and weather rolls come from `defendRandom("rolls")` and its effects (splinters, rain, ripples) from `defendRandom("effects")` (`defend/grid.ts`); the shell's visual effects from `stream("effects")` (`src/random.ts`). Each seeds itself once at start-up from `Math.random` and its name (unless a test pinned it); nothing else calls `Math.random` (`tests/random-streams.test.ts`).

**Saves.** `src/save.ts` loads defensively: `defaults()` defines every field and `decode()` keeps only what is well formed (a newer version starts afresh). When adding save state, add it to `defaults()`, the `Save` type and `decode()`. Player settings are one row each in `SETTINGS` (`src/settings.ts`), from which the `Settings` type, defaults and decoder come; `tests/settings.test.ts` checks every row round-trips.

## Conventions

- Keep this file current. When a change adds, renames, or removes modules, alters architecture, changes commands/scripts or test setup, or changes save rules, update AGENTS.md in the same change, and keep the README's "How it's built" accurate. `CLAUDE.md` only imports this file; don't add content there.
- `CONTEXT.md` is the domain glossary (terms only, no implementation). Use its words in code, comments and docs, and add a term there when a change names a new domain concept.
- All text uses the bundled Cinzel font (`assets/fonts/Cinzel/`); no remote fonts.
- Goldens (`tests/fixtures/*.golden.json`) pin current output; an intended change to city generation, the battle, fences or saves fails them until re-recorded with `UPDATE_GOLDEN=1`. Re-record as part of that change and say which and why in the commit message. A refactor re-records nothing.
- Run the area's tests while iterating (`tests/defend*.test.ts` for Defend, `tests/progression.test.ts tests/settings.test.ts` for progression and saves), then `npm test` and `npm run build` before committing.

## Agent skills

### Adding an upgrade

`.claude/skills/add-upgrade/` defines a new Armory upgrade, Training row or skill-tree node: it writes a spec for approval, then builds it. Its `references/panels.md` describes each panel; keep it current when those mechanisms change.

### Issue tracker

Issues live in GitHub Issues on `sethrimer3/TowerDefense`. See `docs/agents/issue-tracker.md`.

### Triage labels

Uses the five default labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: one `CONTEXT.md` and `docs/adr/` at the repo root, both created only when needed. See `docs/agents/domain.md`.
