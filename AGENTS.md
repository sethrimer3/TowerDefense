# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository.

## Project

Tower Defense: a mobile-first city-defense game in TypeScript + Vite. No backend, no game engine, no framework. Canvas draws the board; the DOM (built as HTML template strings in `src/ui/` and `src/defend/ui.ts`) provides controls, stats, and pages. All state persists in `localStorage` under `towerdefense.v1`. Deployed to GitHub Pages at `https://sethrimer3.github.io/TowerDefense/`.

## Commands

Requires Node 22.18+ (CI uses 24). Tests run `.ts` files directly via `node --experimental-transform-types` (no build step; the experimental warning is expected).

```sh
npm run dev            # Vite on 127.0.0.1:5173 (PORT env overrides)
npm run build          # tsc --noEmit && vite build -> dist/
npm test               # all tests/*.test.ts via node:test
node --experimental-transform-types --import ./tests/pin-random.ts --test tests/defend-replay.test.ts                     # one file
node --experimental-transform-types --import ./tests/pin-random.ts --test --test-name-pattern="Training" tests/*.test.ts  # one test
npm run test:pointer   # Defend board pointer gestures vs tests/fixtures/defend-pointer.golden.json (needs `npm run dev` running)
```

- Every Node test process preloads `tests/pin-random.ts`, which swaps `Math.random` for a fixed-seed stream before any module loads and pins the random streams' start-up seeds by name (`globalThis.__pinnedSeeds`, read by `src/random.ts` and `src/defend/grid.ts`), so a failure always reproduces. Run single files with the same `--import`. `tests/test-size.ts` (`FULL`, `ciOnly`) sizes slow property checks: CI sets `CI` and runs them in full.
- `test:pointer` defaults to installed Microsoft Edge; set `PLAYWRIGHT_CHANNEL=chrome`, or `PLAYWRIGHT_EXECUTABLE=/path/to/chrome` (in the cloud container: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`). It hits the dev server at `http://127.0.0.1:5173/` (or `TEST_URL`) and seeds state by writing the `towerdefense.v1` save into localStorage. Its hashes depend on the page layout and machine: when a change moves the page, record it with `UPDATE_GOLDEN=1` on the unchanged code first, then compare. Output goes to `test-results/` (git-ignored).
- Source imports use explicit `.ts` extensions (`allowImportingTsExtensions`), required so Node can run them directly. Keep this in new imports.
- `tsconfig` only includes `src/`; tests are not type-checked by `npm run build`.
- CI (`.github/workflows/static.yml`) runs `npm test` and `npm run build` on push to `main`, then deploys `dist/` to GitHub Pages (the repository's Pages source must be **GitHub Actions**). Vite `base: "./"` keeps asset paths relative, so the build works under `/TowerDefense/`; asset URLs must not be root-absolute.

## Architecture

**Shell.** `main.ts` builds the shell (`ui/shell.ts`: the currency bar of Gold, iron, steel, Knowledge and the Commander level with its experience bar, the pages and the tab row: Defend, Mine, Library, Upgrades, Settings), loads the save, owns the current tab and `navigate()`, runs the requestAnimationFrame loop (the Mine's and the Library's work on every tab, Defend's and the Mine's frames, the Upgrades page's particles, and a once-a-second tick that settles Training), and passes pages an `AppContext` (`ui/app.ts`). It also creates the `DefendPage` with its `DefendHost`: the Defend save slice, the wallet (Gold and bars; Dev mode and free purchases spend nothing), `bonuses()`, and `earnKills`/`earnWave`, which pay through `progression.ts`. `defendDebug(seconds, weather?)` in the console fast-forwards a battle, `mineDebug(minutes, hire?, weather?)` the mine (forcing the weather), and `libraryDebug(shelves, librarians, seconds, fire?)` furnishes and runs the library (and sets a table alight).

**Library** is a cathedral nave the player fills, in `src/library/`, saved as `save.library` (null until it first shows); it earns Knowledge, `knowledgeRate` = built shelves × librarians an hour. `geometry.ts` holds where things stand, in pixels (192 × 300, the floor's top at `FLOOR`; a hallway `HALL` long out of each side wall, with `EXITS` at their ends and a water butt in each, `BUTTS`). `sim.ts` (`LibrarySim`): each shelf unit (two rows of seven books) has a plank count in `units` (-1 none, 0 an outline once bought, `PLANKS` built); units stack in ten bays against the back wall in `SHELF_ORDER` up to `SHELF_TOP`, under the stained-glass `WINDOW`. Librarians (2 × 4 pixels, each with a scholarly hat) follow step lists (walk, climb, timed work, `away` beyond a hallway's end): one fetches the wheelbarrow of planks (`barrow`) when building wants planks, and the rest carry planks from it to ladders (one segment a plank, up to the built shelves), outlines and burnt tables; another wheels in the book cart (`bookCart`) of new books when shelves stand empty, which the rest shelve; now and then, the stacks full, one loads the cart with old books and wheels it out for new ones (`booksIn`/`booksOut`); otherwise they sort the stacks (each colour has its bay, `homeBay`, and books are shelved there where there is room; `sorted`), read books, or index them at the tables (every third librarian, who now and then rebinds one in a new colour, `mended`). Each librarian has `energy`, drained by work (`TIRING`) and restored by a cup of tea fetched from outside or, at night, a doze in a free seat; by night (`night`, which the page sets from `daylight`) about half go home down a hallway (`home`) and return by day; now and then two stop to talk (`with`) or one gazes up at the window. After a death the others mourn at the ashes (`remains`), then one sweeps them up and scrubs low soot off the stone (`Fire.scrub`). The two water butts hold `BUTT_FULL` buckets: fire fighters draw from them (and run out to the well when both are dry), those who fled refill them during a fire, and one refills them afterwards. Every book is in a slot, a hand, on a table or in the cart. Once a minute a whole table catches fire with `accidentChance(fireproof)` (1% × 0.9 a rank of Fireproof Wood); `fire.ts` (`Fire`) simulates it on a 2-pixel grid of heat and fuel (rising heat, wet cells, thrown droplets that douse with `fireDrill(fireTraining).douse`). Librarians notice it after a moment, then flee down a hallway or (a share set by Fire Training) fetch buckets from the butts and throw them; heat kills (`deaths`, `remains`). When it is out, `settleFire` removes every shelf left under a quarter (and what stood on it: bought again) and leaves the rest short the planks it lost, for free rebuilding; burnt books, ladders and carts are gone, and `lost` says what it cost. It steps on every tab (the page's `advance`, not while the game is closed) and draws from its own `random(seed)`; `furnish(n)` builds and stocks shelves at once (tests, `libraryDebug`). `render.ts` (`LibraryRenderer`) bakes the nave once (ashlar walls and piers with a height map, doorways, the vault, the floor, the lancet window with its rose in an oak frame and sill, the hallways) and lights it per pixel each frame: ambient and window light by `daylight(now)` (one day and night every `DAY_MS` of wall-clock time) plus the torches, candles and the fire's blazes through the blocks' slopes; it paints outlines, half-built shelves, char and soot, and draws carts, librarians with what they hold, flames, smoke, embers and water over it; the hallways show only where librarians have lately walked. `ui.ts` (`LibraryPage`) is the tab and pays Knowledge on the wall clock, catching up `MAX_AWAY_MS` of time away at the saved rate. `tests/library.test.ts` covers the stacking, building, carts, the librarians' work, fires and training, the accident rate, Knowledge and the save (including saves from before building, which held a `shelves` count).

**Mine** is the idle side of the game, in `src/mine/`, saved as `save.mine` (null until it first runs). `world.ts` holds the grid (128 × 480 cells, one material each), the world a seed generates (`generate`, `strata`: sky, grass, dirt with rocks, stone with iron and deeper gold veins, bedrock) and the falling-sand `World.step`: dirt, grass and spoil fall and slide only onto drops of two or more, so slopes settle one across and two up; rocks drop straight; only awake 16 × 16 chunks are stepped. Gravel and loose dirt (pockets in the stone and dirt) slide on any drop and, like falling rock, crush the ladders and timber they land on; lava pools deep down creep slowly and turn to stone where water meets them. A separate `water` layer (one flag a cell) flows down, spreads level and sinks under falling ground. `buildings.ts` lays out the surface buildings either side of the shaft (`layout`: the shaft house, the barracks with a lounge and bays of bunks, `bays(crew)` of them, the warehouse, the forge and the smithy), each with spots (bunks, stools, stations) and the scripted path to each from the door (`along`, `pathTicks`): a miner inside a building is out of the grid, its feet left at the door. `sim.ts` (`MineSim`) is the operation: a plan grid marks cells to dig or fit (ladder, rail, torch, lamp); the planner sinks the laddered shaft level by level and drives a tunnel out both sides of each; each miner (1 × 2 cells) picks the nearest unclaimed job by a breadth-first search over where it can stand (walk, step up two, climb or put up ladders underground, drop), shores loose ground beside its digs with timber, follows ore it bares, carries ore to the forge (and spoil to the heap) or into a level's cart, which rolls to the shaft for the hoist. Each miner has a trade (`job`: mine, forge, smith) from the player's allocation (`setJobs`, `jobs`; the second hire goes to the forge and the fifth to the smithy while they have nobody): forge hands smelt the ore piles (`ore`) into bars (`bars`) and smiths work bars into what `collect()` pays, each at a station inside (`stepInside`, `craft`; a trade with nobody works at a quarter pace); fittings and shoring use supplies (`kit`) fetched from the warehouse; at night (`night`) all but the night shift (`nightShift`: 20%, plus 5% a rank of the Coffee skill) sleep in their bunks; hungry miners eat in the lounge; the shaft house keeps a share of the runoff out of the shaft (`seal`: 20%, plus 15% a rank of Waterproofing) and its roof, like every building's, takes the lightning. The sky turns through day and night (`daylight`, one day every `DAY_TICKS`) and spells of `weatherOf` the seed (clear, cloudy, rain, storm; `skyAt` eases between them): rain falls as water that soaks into soil, runs down the shaft and floods the workings, where miners bail it (and douse fires) as jobs; in storms lightning strikes (and can set wood alight) and miners at the surface sit it out in the lounge. Hazards (`hazards`, `struckBy`, `survey`, `stepFire`) can kill a miner by crushing, drowning, starving trapped (`fed`, `MEAL_TICKS`), lava, fire or lightning; `kill` spares the last miner, any death within `DEATH_GAP` of the last (a new mine starts with that grace) and a second death in one catch-up, records the cause in `lost`, and posts `news` the page and renderer show. Fewer miners make the next hire cheaper (`sim.price`). `collect()` pays what the smithy turned out: `GOLD_PER_NUGGET` Gold per gold ingot, an iron bar per bar worked (each `ORE_PER_IRON_BAR` iron ore smelted) and a steel bar every `BARS_PER_STEEL` (into the save's Gold, iron and steel bars); `hirePrice` prices miners in Gold. The mine uses no shared random stream: generation and choices hash the seed, cells and tick. `render.ts` (`MineRenderer`) paints visible rows one pixel a cell into an offscreen image, lit by a two-channel light map (daylight, and torches, lamps, lava, fires and miners) spread cell to cell, under a pan/zoom camera with stars by night, clouds, rain and lightning, the headframe, the buildings (each front wall fading while anyone is inside, to show the bunks, lounge, shelves, furnace and ore piles, anvil and bars, and the miners sleeping or at work; the shaft house's lantern and the barracks' windows lit at night), graves for lost miners, carts, bucket, miners (coloured by trade) and dust drawn over it (dust from `stream("effects")`). `ui.ts` (`MinePage`) is the tab (with the trades' steppers), and `advance(now)` runs the sim on the wall clock within a frame budget, catching up up to `MAX_AWAY_MS` of time away after loading. `tests/mine.test.ts` covers the physics (water, gravel, lava, fire), generation, the crew's work and pay, the buildings, trades, night shift, supplies and waterproofing, weather, floods, deaths and their spacing, and the save.

**Defend** is the game, self-contained in `src/defend/` with its own save slice (`save.defend`) and page (`DefendPage`, `defend/ui.ts`); see `docs/DEFEND.md`. Its battle simulation, `DefendSim` (`defend/sim.ts`), owns the world state and what happens to it (damage, rebuilding, blasts, movement), and steps the units in a fixed order. Each unit type's decisions live in its own module: `enemies.ts`, `troops.ts` (barracks, swordsmen, archers), `civilians.ts`, `towers.ts` and `wizard.ts` (wizard towers alternating `sim.flames` and `sim.frosts`; an enemy's optional `chill` slows it, and stays absent when unset so runs without ice hash exactly as before). `pathing.ts` holds the pure grid A*, the enemies' flow field and the collision test. A sim takes the Armory's levels and, optionally, `Bonuses` (`catalog.ts`: multipliers on troop HP and damage, drill time, tower damage and reload, wall and keep HP, rebuild time and bomb damage; `NO_BONUSES` is all 1, so a sim without them plays exactly as before), and counts the enemies slain by kind (`sim.slain`, which the page pays for each frame; not part of the replayed state). `DefendRenderer` (`defend/render.ts`) owns the camera and the order of the drawing passes: `city-layer.ts` paints the cached static city (it re-exports the pond and tree geometry of `park-geometry.ts`, `pondDisc`/`pondPath`/`POND`, `hasTree`/`treeCanopy`, that the live effects line up with), then **park life** over it (`park-art.ts`, `parkArt`: the ponds and trees as pixel art at 8 pixels a cell, baked once per city with the open-water mask everything on the water keeps to, its geometry from `park-geometry.ts`; `pond-water.ts`, `PondWater`: faint pixel rain rings all over the water while it rains, and the bank mirrored into the water from the city layer in strips shifted by the shimmer and the rings, tinted and masked to the open water; `pond-ducks.ts`, `Ducks`: a few pixel ducks when it isn't raining, with drift, paddle, dabble, preen, follow, flee and sleep states and rare wake rings; `park-grass.ts`, `ParkGrass`: blades planned per park cell clear of canopies and shores, swaying with the wind and gusts, parting around the walkers the renderer passes, written into one pixel buffer at 8 pixels a cell and rebuilt at most 30 times a second; both skipped when the `effectsOff` setting is on), `fences.ts`, `lighting.ts` the torchlight and shadows, `ground-relief.ts` (`GroundRelief`: the flagstones' bump map outside the city, four facing masks baked from the floor art's brightness by `paintFloor` in `city-layer.ts`, lit per light through cached weight sprites; fixed lights baked per map version, moving ones per frame), `battle-art.ts` each frame's damage, scorches, units and effects, `wizard-art.ts` (`WizardArt`: the wizard towers' fire particles and the ice wave's shaded crystal shards, advanced on battle time; `flameLights` turns each flame into carried and relief lights), `edit-overlay.ts` the building grid and drag overlay, and `structure-art.ts` the building art, banner and palette icons (the keep, `keepPixels`, and its waving banner, `flagPixels`, are pixel art at 8 pixels a cell like the parks; `tests/defend-keep-art.test.ts`). Park life is presentation only: it never changes the city or the battle, and draws its randomness (rain rings) from `defendRandom("effects")`. All units draw from one seeded random stream, so the step order and each unit's draws decide a replay. `tests/defend-replay.test.ts` steps fixed cities, upgrade levels, seeds, bombs and demolitions through `update()` and hashes the whole sim state every 5 s against `tests/fixtures/defend-replay.golden.json`, reporting when a run first diverges. Regenerate it with `UPDATE_GOLDEN=1` only for an intended gameplay change. The battle must play the same in every JavaScript engine and Node version (CI runs Node 24), so battle code uses only `+ - * /` and `Math.sqrt`, with `intPow`, `sq` and `dist` from `src/exact.ts`: no `Math.pow`/`**`, `hypot`, `exp`, `log` or trigonometry (the wizard aims by unit vectors and tests cones by slope). Drawing may use `Math` freely. Check a replay change under both: `npx -y node@24 --experimental-transform-types --import ./tests/pin-random.ts --test tests/defend-replay.test.ts`. On the page, board pointers go through `board-pointers.ts` (`BoardPointers`), a small state machine: idle, viewing (one pointer pans, two pinch-zoom), or dragging a palette item, structure, keep, city tile or bomb under a ghost icon. It only turns pointers into board cells; each drag is an `EditSession` (`edit-session.ts`), a pure transaction over the layout it started from: what a press lifts (`EditSession.lift`), the legal tiles and the layout each makes, the overlay shown while held, and the `Drop` a release makes, which the page applies. `tests/defend-edit-session.test.ts` drives whole drags in Node. `drag-rules.ts` holds the rules behind it (unit-tested in `tests/defend-drag-rules.test.ts`). The city itself comes from `layout.ts` (the player's tiles and structures; `fitLayout` picks each structure's cells) and `citygen.ts` (streets, parks, houses, ponds and wall stones, as a pipeline of stages). `tests/defend-city.test.ts` hashes seeded random walks of layout edits, their fits and failure reasons, and the cities generated along the way against `tests/fixtures/defend-city.golden.json`; regenerate it with `UPDATE_GOLDEN=1` only for an intended change to city building. `fences.ts` lays decorative fences along the street sides of parks and snaps them into splinters under walking enemies and blasts, and `progress.ts` holds the saved Defend state, its purchases, and `decodeDefendSave`, which rebuilds the saved layout piece by piece and drops it unless it is well formed, owned and still fits. `tests/defend-fences-save.test.ts` hashes fence sections, seeded fence runs and `decodeDefendSave` over a corpus of saves against `tests/fixtures/defend-fences-save.golden.json`. `tests/defend-park-life.test.ts` checks where grass is planned, the pixel ponds' open water, and the ducks keeping to it, fleeing walkers and sleeping at night, and `tests/defend-wizard.test.ts` the wizard tower's turns, cone and chill.

**Progression** (`src/progression.ts`, pure functions over the save): Commander levels from lifetime experience (`xpForLevel`, `levelForXp`), training points (`TRAINING_PER_LEVEL` a level; `trainingPoints` counts ranks owned and in training, less `save.freeTraining`), the `TRAINING` rows (each rank `per` percent on its target, `max` ranks), timed ranks (`startTraining`, `cancelTraining`, `settleTraining`; durations and the base slot count in `training-jobs.ts`: 60 s for a row's first rank, each after 50% longer; `trainingSlots` adds the Tactician skill), the skill trees' purchases (`skillPurchase`, `buySkill`), and what a defense pays (`payKills`: `KILL_GOLD` and `killXp`; `payWave`: `waveGold`, iron, steel on boss waves, Knowledge past the best wave). `multiplier(save, target)` adds Training's and the skills' percents for a target (a time's percent divides), and `bonuses(save)` folds them into the battle's `Bonuses`; `gold` and `xp` multiply the rewards. `src/skill-trees.ts` defines the skills (`SKILLS`: name, glyph, max ranks, Knowledge `base` with `skillCost = base × (rank + 1)`, effect) and the `TREES` (Command, Stewardship; Mine: Coffee and Waterproofing, read as ranks by the mine; Library: Fireproof Wood and Fire Training, read as ranks by the library) with node positions and requirements; `ui/skill-tree-page.ts` (`SkillTreePage`) draws Training and the trees (pan and zoom with `ui/pan-zoom.ts`, particles from `tree-particles.ts` and `training-particles.ts`). `tests/progression.test.ts` covers it.

**Sound and flourishes.** `src/sound.ts` makes every sound in code with Web Audio (no sound files): `play(cue)` builds each `Cue` (the oak buttons' `knock`, the tab row's `stone`, `coin` for spending, `chime`/`unlock` for skills, `wave`, `record`, `levelUp`, `trained`, the boss wave's `horn`, the fallen keep's `fallen`) from noise bursts, oscillators and bell partials, into a generated stone-hall echo, and stays silent with the `soundOff` setting. `src/ui/flourish.ts` draws the DOM celebrations: `sparks` (embers off a pressed button, gold for a win, arcane for a level) and `replay` (restarts a CSS animation class); none play under Reduce motion. `main.ts` knocks and sparks on every button click, glints a rising currency and plays level and Training cues; the Defend page and skill trees play their own. The animations themselves are in `theme.css`'s Motion section, off when the root has `.reduce-motion` (set from the setting) or the system prefers reduced motion. Both draw from `stream("effects")`.

**Torch light toolkit.** `src/lighting.ts` (the candle colour ramp, flicker and sway: `getTorchFlicker`, `getTorchSway`, `LIGHTING_CONFIG`), `src/torch-light.ts` (`lightFalloff`, `glowColor`, and the occlusion-aware baked glow `torchLightField`/`bakeTorchLight`) and `src/visibility.ts` (`Torch`, `TORCH_LIGHT`, `computeVisibilityPolygon`, `insidePolygon`) are kept from the dungeon game for Defend and future use; `defend/lighting.ts` builds the city's lights on them.

**Randomness.** Defend's city, battle and weather rolls come from `defendRandom("rolls")` and its effects (splinters, rain, ripples) from `defendRandom("effects")` (`defend/grid.ts`); the shell's visual effects from `stream("effects")` (`src/random.ts`). Each seeds itself once at start-up from `Math.random` and its name (unless a test pinned it); nothing else calls `Math.random` (`tests/random-streams.test.ts`). A new mine's seed comes from `stream("game")`.

**Saves.** `src/save.ts` loads defensively: `defaults()` defines every field and `decode()` keeps only what is well formed (a newer version starts afresh; Knowledge was once `valor`, which `decode()` still reads). When adding save state, add it to `defaults()`, the `Save` type and `decode()`. The mine's grid and plan are stored run-length encoded as base64 (`encodeGrid`/`decodeGrid`), as is its water layer (optional, so older saves load dry), and `decodeMineSave` drops a mine unless it is whole (its burning cells, losses, mercy, miners' meals, trades and supplies, the allocation, and the forge's and smithy's stock are checked when present); the library's book slots use the same encoding (`decodeLibrarySave`). Player settings are one row each in `SETTINGS` (`src/settings.ts`), from which the `Settings` type, defaults and decoder come; `tests/settings.test.ts` checks every row round-trips.

## Conventions

- Keep this file current. When a change adds, renames, or removes modules, alters architecture, changes commands/scripts or test setup, or changes save rules, update AGENTS.md in the same change, and keep the README's "How it's built" accurate. `CLAUDE.md` only imports this file; don't add content there.
- `CONTEXT.md` is the domain glossary (terms only, no implementation). Use its words in code, comments and docs, and add a term there when a change names a new domain concept.
- All text uses the bundled Cinzel font (`assets/fonts/Cinzel/`); no remote fonts.
- The page's look lives in `src/theme.css`, loaded after `src/style.css` (layout): dressed stone for the hall and tabs, oak boards nailed at the corners for buttons and panels, brass trim and an ember glow for chosen and leading buttons, red lacquer for danger, parchment for dialogs, banners, the Defend settings and tooltips, and an alchemical circle behind the skill trees. Its textures are small tiling SVGs in `assets/theme/` (`stone`, `wood`, `parchment`, `sigil`, `rule`, `seal`, and `frame`, the board's iron corner brackets). Style new UI from its tokens (`--wood`, `--stone`, `--parchment`, `--nails`, `--brass-nails`, `--ink`) rather than flat colours.
- Goldens (`tests/fixtures/*.golden.json`) pin current output; an intended change to city generation, the battle, fences or saves fails them until re-recorded with `UPDATE_GOLDEN=1`. Re-record as part of that change and say which and why in the commit message. A refactor re-records nothing.
- Run the area's tests while iterating (`tests/defend*.test.ts` for Defend, `tests/mine.test.ts` for the Mine, `tests/library.test.ts` for the Library, `tests/progression.test.ts tests/settings.test.ts` for progression and saves), then `npm test` and `npm run build` before committing.

## Agent skills

### Adding an upgrade

`.claude/skills/add-upgrade/` defines a new Armory upgrade, Training row or skill-tree node: it writes a spec for approval, then builds it. Its `references/panels.md` describes each panel; keep it current when those mechanisms change.

### Issue tracker

Issues live in GitHub Issues on `sethrimer3/TowerDefense`. See `docs/agents/issue-tracker.md`.

### Triage labels

Uses the five default labels: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`. See `docs/agents/triage-labels.md`.

### Domain docs

Single-context: one `CONTEXT.md` and `docs/adr/` at the repo root, both created only when needed. See `docs/agents/domain.md`.
