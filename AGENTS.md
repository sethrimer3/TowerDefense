# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository.

## Project

Tower Defense: a mobile-first city-defense game in TypeScript + Vite. No backend, no game engine, no framework. Canvas draws the board; the DOM (built as HTML template strings in `src/ui/` and `src/defend/ui.ts`) provides controls, stats, and pages. All state persists in `localStorage` under `towerdefense.v1`. Deployed to GitHub Pages at `https://sethrimer3.github.io/TowerDefense/`.

- Every Node test process preloads `tests/pin-random.ts`, which swaps `Math.random` for a fixed-seed stream before any module loads and pins the random streams' start-up seeds by name (`globalThis.__pinnedSeeds`, read by `src/random.ts` and `src/defend/grid.ts`), so a failure always reproduces. Run single files with the same `--import`. `tests/test-size.ts` (`FULL`, `ciOnly`) sizes slow property checks: CI sets `CI` and runs them in full.
- `test:pointer` defaults to installed Microsoft Edge (the stress and render-cache scripts to installed Chrome); set `PLAYWRIGHT_CHANNEL=chrome`, or `PLAYWRIGHT_EXECUTABLE=/path/to/chrome` (in the cloud container: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`), which every browser script accepts. It hits the dev server at `http://127.0.0.1:5173/` (or `TEST_URL`) and seeds state by writing the `towerdefense.v1` save into localStorage. Its hashes depend on the page layout and machine: when a change moves the page, record it with `UPDATE_GOLDEN=1` on the unchanged code first, then compare. Output goes to `test-results/` (git-ignored).
- Source imports use explicit `.ts` extensions (`allowImportingTsExtensions`), required so Node can run them directly. Keep this in new imports.
- `tsconfig` only includes `src/`; tests are not type-checked by `npm run build`.
- CI (`.github/workflows/static.yml`) runs `npm test` and `npm run build` on push to `main`, then deploys `dist/` to GitHub Pages (the repository's Pages source must be **GitHub Actions**). Vite `base: "./"` keeps asset paths relative, so the build works under `/TowerDefense/`; asset URLs must not be root-absolute.

## Architecture

**Ambush economy.** `campaign/economy.ts` owns level gold (500/600/700), rough potential-DPS prices rounded to tens, worn-upgrade premiums and native spawn-stat kill bounties. `campaign/price-estimates.ts` contains pricing estimates only; it never drives combat. Combat runs the actual Defend tower/troop modules. Owning a type unlocks repeat purchases. Build/sell during waves uses stable native lot IDs; removing a building withdraws only its own native garrison and timers. Before battle refunds are exact; battle refunds are 70% rounded down to tens. Native enemy death pays once; escaped enemies never pay or count as slain. Wallet/paid costs remain transient and separate from Mine metals. Retry rebuys saved layouts only within budget. `tests/ambush-economy.test.ts` checks economy and inventory isolation; `tools/ambush-prices.ts` regenerates `docs/design/AMBUSH_ECONOMY.md`. Prices remain provisional estimates; native specialty effects apply even where their full matchup value is not captured by the estimate.

**Player profile.** Optional `Save.profile` contains a validated 2–24-character name and a 16×24 flag (palette base plus up to 12 pattern/color layers with optional 25/50/75/100% opacity (absent means 100% for old flags)). `profile/model.ts` owns pure masks, bounded decoding, bottom-to-top RGB alpha compositing and matching canvas/SVG output; no images or arbitrary markup enter saves. `profile/editor.ts` owns a dedicated native dialog with palette, stamp previews, layer ordering/recolor/removal and bounded undo history. Missing/invalid profiles (including old saves) trigger mandatory setup before the welcome-back dialog; game progress is preserved. Profile editing in Siege pauses a running raid and uses a draft; Cancel/Escape discard it. Erase Everything prompts for a new profile. Siege displays the escaped username and the same pixel flag beside MMR. `tests/profile.test.ts` checks names, save decoding and compositing; `node tests/profile.mjs` exercises first entry, layering/undo, edit/cancel, Siege display and old saves on desktop/phone. Main-app browser tests must complete setup or seed a valid profile in their isolated save.

**Combat tab and campaigns.** `ui/combat-tab.ts` owns the session-only Defend → Ambush → Siege cycle and sliding/fading icons. `main.ts` keeps navigation ID `defend` and advances only the selected mode. `campaign/ambush-ui.ts` shows a three-column, ten-zone level selector before opening the native campaign battle page. `campaign/levels.ts` owns 30 stable level IDs/seeds, deterministic non-crossing edge-to-keep tracks and outpost anchors, best-star recording, derived unlocking and legacy migration. `Save.campaigns` now defaults to `{ ambush: { stars: {} }, siege: { cleared: 0, layouts: [] } }`. Old Ambush pad layouts are discarded; `cleared: n` grants one star to the first n Mossbound levels (bounded to three). Stars retain the best result and only improvements add to the total. Until later plan phases add outpost scoring, completing the existing three-wave battle grants one star. Phase 2 uses each seeded generated track and zone in the actual native battle map. Entry roads reach an edge cell; enemies spawn half a cell inside it so native body collision accepts them, and road paving never overwrites the keep owner. `campaign/plans.ts` retains legacy Siege decoding. `battlefield.ts` generates temporary roadside lots on the new tracks until Phase 3 replaces pads. `entry-arrow.ts` draws a black-outlined pixel arrow in the overlay, pulsing unless motion is reduced. `previews.ts` shares one native renderer and at most thirty cached snapshots, generated lazily with IntersectionObserver; preview/battle maps use the same factory, zone and seed. Native texture loads invalidate active previews and detached selectors remove their repaint subscription. Campaigns share the actual `DefendSim`, `DefendRenderer`, tower/troop/projectile/spell modules, saved bonuses and worn upgrades. `ScenarioRules` hooks remain absent in ordinary Defend so replay goldens do not change. Native Ambush geometry and placement use exact distance helpers. `tests/ambush-levels.test.ts` covers all 30 tracks, stars and migration; `node tests/ambush-levels.mjs` checks the selector and battle/selection navigation at desktop/phone sizes. New Ambush control labels go through `i18n/ambush.ts` with English fallback.

`campaign/raid.ts` runs two native Defend sides on one native map. Native soldiers/buildings are exposed to the other side through targeting adapters; damage routes to their owning side's existing `hurtDefender`/`damageBuilding`. Collision, repairs, walls and gates synchronize between sides. Rendering combines real native effects/units; target adapters never draw as monsters. The upper castle has native streets, houses, walls, gates, keep, towers and troop buildings. Every owned infantry copy musters below, retaining its own worn upgrades, and trains/replenishes its native garrison. Overflow rosters stack same-kind muster footprints rather than dropping copies. No invented finite reserve or separate campaign attack physics. Destroying the keep wins; four minutes expires the raid. `campaign/ui.ts` uses native camera/pointer gestures, building/path icons, range inspection, researched spells and the existing upgrade tree; its palette sits beside the battlefield. AmbushPlan Phase 0 removes both mode headings and the How to play/Buildings and upgrades blocks, including the redundant numbered-space DOM list. Placement and inspection use the numbered board lots; Siege retains its ranked reload/forfeit explanation in opponent details. Campaign route geometry and placement hit testing use `exact.ts` distance helpers. Campaign saves store Ambush best stars without retaining battle layouts or changing inventory/Defend placements. Mode navigation pauses; reload restarts Ambush. `campaign/castles.ts`, `siege-rating.ts` and `siege-progress.ts` preserve seeded bot offers and idempotent rated results; recovered started raids count as losses, completed targets are unrated practice. The legacy castle strength prior now selects a native defense budget and requires fresh calibration; obsolete prototype win-rate measurements were removed. See `docs/design/SIEGE_MATCHMAKING.md`. `tests/campaign-native.test.ts` compares actual specialized projectile payloads against Defend and exercises native wall destruction/mitigation; `tests/campaign.test.ts` and `siege-rating.test.ts` cover copies, saves and ratings. `node tests/campaign.mjs` (alias of `campaign-native.mjs`) checks the cleaned pages, real board mouse/touch placement and selling, native rendering/camera/armies at 1280 × 800 and 390 × 844 (screenshots in `test-results/`); `node tests/combat-tab.mjs` checks main-app navigation.

**Ultimate Archer Tower.** `chronoTower` merges fully ranked Fire/Hawk/Wisp towers through `ATTUNED`. `chrono-upgrades.ts` defines four independent shared branches saved as optional `DefendSave.chronoRanks`, snapshotted into `Bonuses.chrono`. `defend/chrono.ts` owns bounded, transient per-building shot queues, low-priority private aim points (never inserted into enemies), swept field interception, fixed-angle rapid release and Divine rays. Compatible arrows/shells/ballista bolts keep their payloads; `chronoReleased` prevents every field from recapturing releases. Idle cannon support shells carry `chronoAim` and expire harmlessly when rejected. Incompatible idle damage counts one hit per attack; capacity is independent of the physical reserve, and Divine damage/hits reset on launch. Normal targets, cooldowns and enemy resistance/shield rules remain authoritative. Continuous minelayers and harmless nanobot shells do not create contribution attacks. `chrono-art.ts` draws bounded orbits and golden trails/dust using existing battle rendering, with Reduce Motion; art seeds append the tower at the end. Shared tree, Tiles marks, range and magic-circle progress use existing mechanisms. Tests: `defend-chrono.test.ts`, `node tests/chrono-tower.mjs`. Only save-decoding goldens change for the new catalog key; fence/replay hashes stay unchanged. [Specification](docs/upgrades/ULTIMATE_ARCHER_TOWER.md).

**Localization.** `src/i18n/` owns nine local catalogs, stable language codes, typed `t()` messages, interpolation and English fallback. `settings.language` defaults/migrates to English; Settings opens a native dialog with three columns of native-name buttons. `ctx.changeLanguage()` saves and updates annotated labels without reloading or rebuilding canvas pages. Dynamic Mine/Library text cache keys include the locale. Keep IDs/names/gameplay data unlocalized; use explicit messages and `data-i18n` on text-only labels, never automatic DOM text replacement. This first pass covers Settings, navigation and primary controls; longer descriptions remain English. Alembic includes the Latin catalogs’ accented glyphs; CJK uses local system fonts through `--font`, retaining the saved custom-font preference. `tests/i18n.test.ts` and `node tests/languages.mjs` check migration/catalogs, real desktop/phone picker, live battles, reload and menu fit. [Guide](docs/LOCALIZATION.md).

**Repeated purchases.** `src/ui/hold-repeat.ts` delegates pointer holds by stable purchase attributes so buttons can redraw between purchases. Mine hires/building upgrades, Library shelves/hires/lab expansion, Tiles purchases and repeatable Smithy/Study upgrades share it. The first held purchase waits 450 ms, then gaps shrink from 260 ms by 0.86 per purchase down to 35 ms. Short clicks and keyboard activation remain single purchases; held releases add none. Each purchase uses its normal current price and availability checks. Disabled, removed, hidden or inert controls, pointer movement/cancellation, scrolling, blur and page hiding stop the hold. Timed work and rebuilding retain their existing locks. `tests/hold-repeat.html` is an isolated redraw fixture; `node tests/hold-repeat.mjs` also tests real Mine/Library mouse/touch purchases in fresh browser contexts without player saves.

**Metal economy.** `src/metals.ts` shares prices, affordability, payment and Copper/Silver/Gold labels; `save.smithy` is the sole spendable metal wallet. Mine/Library hosts expose `metals` and `spendMetals`. Starting metal is 10 Copper; a second miner costs 2 Copper, the first shelf 1 and the first librarian 2. Mine level upgrades start at 4–6 Copper; later levels add Silver then Gold. Larger crews/collections add precious metals, and lab expansions start at 10 Copper before adding Silver/Gold. Bombs cost 1 Copper (`BOMB_PRICE`). Unlimited money bypasses affordability and spends nothing. DEFEND awards only one upgrade point per new highest wave; `payWave` records the best with payment so duplicate events cannot pay twice. Knowledge comes only from the Library. There is no battle Gold, Gold found, Plunder, Copperworks or Spoils topic. Run `tests/metals.test.ts`, `tests/progression.test.ts`, `tests/tiles.test.ts` and `node tests/metal-economy.mjs` (isolated desktop/mobile browser fixture).

**Quadratic balance and project work.** `src/economy.ts` holds price coefficients, used by Training, Forge, Mine buildings/hires and Library shelves/staff/lab. Training costs `1 + 5 * owned²` of its metal tier and takes `60 * next-rank²` seconds per smith, times its metal's `TIER_WORK` (`training-jobs.ts`: copper 1, silver 2, gold 4). `src/forge-jobs.ts` reserves mixed metals for all ordinary upgrades and War drums, taking `120 * next-rank²` seconds per smith times its bill's most precious metal (`billWork`); its one project shares named smiths with Training via `busySmiths`. `src/research-jobs.ts` reserves Knowledge for every skill and spell path rank, sharing all current researchers on one lab project: `300 * next-rank²` researcher-seconds or 24 researcher-hours for a crown. Zero workers pauses; completion applies effects exactly once; cancellation refunds the saved actual paid bill, including across dev toggles. `save.researchJob/researchClock` and `save.forgeJob/forgeClock` persist work; Training jobs retain `paid`. Main settles all clocks each second and after loading. Study/Smithy show time, staffing and refund controls. No Smithy upgrade is instant: Training and Forge always need a free smith and their time, whatever the dev options; Instantaneous research covers only the Study. The Smithy shows each bill as amounts by small ingot icons (`costHtml`, `.metal-icon`). Run `tests/upgrade-work.test.ts` and `node tests/upgrade-work.mjs`.

**Water and winter ice.** `boats.ts` indexes all pools, filtering decorative or frozen pools out of liquid combat checks. In cold areas (or debug snow), water freezes at its current radius and every boat leaves persistent frozen sheets, including small boats. Quantized, deduplicated winter emissions bound stationary trails. Fireballs, burning ground, wizard flames, dragon breath and explosions thaw intersecting sheets into water with a fresh eight-second lifetime; melted sheets never refreeze. Ice survives later area changes for the rest of the battle. `icyCell` blocks builder jobs and final rebuilding wherever ice overlaps rubble. `ice-motion.ts` retains ground-unit momentum, adds blast impulses on ice, and checks collisions along slides. Fliers and boats do not slide. Natural ponds freeze during cold weather and heat opens liquid cells (`thawedPonds`); their permanent pond water remains. Surfaces are transient battle state, not saved. `flood-art.ts` draws softer banks, separate reflections for disconnected spans, tree reflections, bounded movement wakes and rain rings; ice has fixed facets and cracks. `pond-water.ts` adds footstep rings and frozen pond art. Reduce Motion disables rings and shimmering; disabling park effects still leaves gameplay ice visible. Run `tests/defend-ice.test.ts` and `node tests/defend-water.mjs` (dev server required, desktop/mobile galleries in `test-results/`). Water buffer checks compare reused storage with fresh current art because the visuals intentionally differ from the frozen reference.

**Bomb research.** Study → Spells → Bombs retains topic ID `battle` for Tiles links, with no Realm bomb topic. `ui/bomb-tree.ts` adapts the existing Gunpowder skill into a bomb root and three ordered rank nodes; `Ledger.renderSkillTree` shares the existing living graph with the banner, preserving it on redraw and destroying it on topic changes or during timed work. Selecting an owned/future rank cannot buy the current rank. Pending projects use the normal centered research/cancellation UI, completed ranks persist in the existing skill save and drive nested-triangle circle complexity. Gunpowder has no troop prerequisite; Ballistics only needs Fletchers. Smithy Spells → Bombs retains bombDamage and bombSafe; War drums (`speed3`) is in Realm → All troops. No new upgrades, prices, save fields or combat effects. Tests: `upgrade-subjects.test.ts` and `node tests/bomb-tree.mjs` (real desktop/phone timed purchases, cancellation, reload, rank gating and Smithy access).

**War banner research.** The Skills palette lets the banner be placed immediately, then enforces a battle-time cooldown of 10 seconds (Rapid deployment reduces it to 7, 4 and 1). Its standalone Study → Spells → War banner Knowledge tree (`ui/banner-tree.ts`, rendered with the existing `UpgradeGraph` by `Ledger`) has no Ballistics prerequisite. The graph survives selection redraws and is destroyed during timed research or on topic changes; its selected node shows the existing research card, and completed ranks still drive the magic circle. The banner tree has shared cooldown, defense (10% less damage received) and influence radius (5 to 7 cells) upgrades before independent damage (+25%), marching speed (+50% while heading toward the banner) and life (+25% within influence, preserving health percentage on transitions) branches, with regeneration (5% of influenced maximum HP per second) after life. Existing War banner research remains a permanent troop damage bonus. `war-banner.ts` owns influence and health transitions; defender damage routes through `hurtDefender`. Research ranks use the existing skill save decoder. Placement ghosts and planted circles share the researched radius. Skills show a battle-time dark cooldown fill and gold ready outline. Run `tests/defend-war-banner.test.ts` and `node tests/defend-war-banner.mjs` (dev server required, isolated saves). A double tap on the board in battle (`DefendPage.rallyTap`: within `DOUBLE_TAP_MS` and `DOUBLE_TAP_SLOP`) plants a rally flag (`sim.plantFlag`, a `WarBanner` with `flag` set): free, no cooldown, troops march to it as to the banner but it lends no influence (`bannerInfluence` is false, no march bonus, `RALLY_REACH` to seek enemies), drawn as a blue banner without a ring (`drawRallyFlag`). It and the war banner replace each other; it isn't lifted, a double tap elsewhere moves it and one on it (`onFlag` in `war-banner.ts`) takes it away (`sim.liftFlag`). `rally-flag-art.ts` (`RallyFlagArt`, kept by the renderer; presentation only, wall clock, snapped under Reduce Motion) drops a new flag in fading up with a small ring spreading from its foot (`dropPose`, `ringPose`) and sends one taken away or replaced flying up as it fades (`liftPose`); `RALLY_ANIM` holds the timings. The Gameplay setting Triple tap to place the rally flag (`tripleTapFlag`, off by default, the host's `tripleTapFlag`) asks for a third tap in the run (`lastTap.taps`), for players who plant it by accident. Run `node tests/defend-rally-flag.mjs` (dev server required; isolated stress fixture).

**Strike spells and Necromancy.** Strike spells are lasting Skills (`tiles.ts` consumables, never used up) cast from the battle's Skills palette by dragging onto the board (`Drag` `{ from: "necromancy" }`, `Drop` `{ kind: "spell" }`). Each has its own Spells subject topic in `upgrade-subjects.ts` (`Topic.icon` stands in for a palette item): Smithy rows (`undeadHp`, `undeadDamage`, `graveTime`, the Training group `spells`, read as `Bonuses.undeadHp/undeadDamage/graveTime`; a row with `seconds` shows as a time) and Study paths in `knowledge-paths.ts` whose topic is a `SpellId` (`SPELLS`, `isSpell`). A spell has no cards: it casts with the one researched path `save.spellPaths` names (`equipSpell`, `decodeSpellPaths`; the first path researched is chosen automatically, unlearning clears it) at its furthest rank (`spellPath`, snapshotted into `Bonuses.necromancy` at battle start); the Study shows a Cast with picker above the tree. `defend/necromancy.ts`: every enemy death (not fortress parts) leaves a `sim.graves` entry with its difficulty for `NECRO.graveLife` (10) seconds times `Bonuses.graveTime` (Grave time: 20 s, then 30 s); `castNecromancy` (`sim.castNecromancy`, cooldown `necroRemaining`) raises each grave within `NECRO.radius` on open ground as a friendly `Soldier` of kind `"undead"` (`home` -1, `risen` set), up to `NECRO.maxRisen` alive, each crumbling after `NECRO.life` seconds without counting as a lost troop. Paths: Bone archers (range, harder arrows, twin shot), Soul weighing (strength by the fallen's difficulty, `SOUL_WEIGHT` caps) and Amalgam (one giant from the summed difficulty, cleave at II, never crumbles at III). **Mine tunnels and lighting.** Stone takes 330 ticks (three times rock); `HARD_STONE` at about 30% underground depth takes 990, and `DENSE_STONE` at about 60% takes 2970. Softer seams cross the deeper strata, and ore/caves work in all three. `routeTunnel` minimizes excavation cost within three rows of a level, with seeded bends and at most a one-cell grade; roof pockets vary the clearance. `tunnelRows` drives rail reach, progression and carts, while the renderer connects rails in one-art-pixel increments. Digging beneath rails plans replacement trestles. Miners set `WORK_LAMP` beside dark working faces, replace spent lamps during long jobs, and plan/build lasting `LAMP` lanterns along established track with irregular gaps, only where the open height from rock to rock (track, water and fittings count as open) is at least `LANTERN_ROOM` cells (8 pixels), so ordinary 3-cell tunnels get them only in roof pockets, caves and chambers; the bulb hangs 5 or 6 pixels over the floor, and each level's shaft-foot lantern hangs in a pocket dug over the tunnel's mouth. Work lamps last 90 simulated seconds; torches last a seeded 120-240 seconds, and spent torch plans become plain dig marks. Lighting checks flood through open cells, so a lamp behind a wall does not suppress a work light. Torches are the right two pixels of a cell (1x2 art pixels); lanterns have a one-pixel-wide ceiling chain and a bottom flame. Carts are three art-pixel rows tall, including their load, with no visible wheels; metal and ore sample the cave's local daylight and warm lighting per pixel. Saves retain remaining light lifetimes (`lights`), compressed floor offsets (`routes`), cart elevations and `geology: 1`; older routes are reconstructed from rail plans, and older prospects upgrade only untouched deep stone, preserving their excavated passages, ore and fittings.
