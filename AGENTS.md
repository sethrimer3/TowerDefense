# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, etc.) when working with code in this repository.

## Project

Tower Defense: a mobile-first city-defense game in TypeScript + Vite. No backend, no game engine, no framework. Canvas draws the board; the DOM (built as HTML template strings in `src/ui/` and `src/defend/ui.ts`) provides controls, stats, and pages. All state persists in `localStorage` under `towerdefense.v1`. Deployed to GitHub Pages at `https://sethrimer3.github.io/TowerDefense/`.

## Commands

Requires Node 22.18+ (CI uses 24). Tests run `.ts` files directly via `node --experimental-transform-types` (no build step; the experimental warning is expected).

```sh
npm run dev            # Vite on 127.0.0.1:5173 (PORT env overrides)
npm run build          # tsc --noEmit && vite build -> dist/
npm test               # all tests/*.test.ts via node:test
node --experimental-transform-types --import ./tests/pin-random.ts --test tests/defend-replay.test.ts                     # one file
node --experimental-transform-types --import ./tests/pin-random.ts --test --test-name-pattern="Smithy" tests/*.test.ts  # one test
npm run test:pointer   # Defend board pointer gestures vs tests/fixtures/defend-pointer.golden.json (needs `npm run dev` running)
npm run test:performance # Browser crowd benchmark, 500 through 10,000 enemies (needs dev server)
```

- Every Node test process preloads `tests/pin-random.ts`, which swaps `Math.random` for a fixed-seed stream before any module loads and pins the random streams' start-up seeds by name (`globalThis.__pinnedSeeds`, read by `src/random.ts` and `src/defend/grid.ts`), so a failure always reproduces. Run single files with the same `--import`. `tests/test-size.ts` (`FULL`, `ciOnly`) sizes slow property checks: CI sets `CI` and runs them in full.
- `test:pointer` defaults to installed Microsoft Edge; set `PLAYWRIGHT_CHANNEL=chrome`, or `PLAYWRIGHT_EXECUTABLE=/path/to/chrome` (in the cloud container: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`). It hits the dev server at `http://127.0.0.1:5173/` (or `TEST_URL`) and seeds state by writing the `towerdefense.v1` save into localStorage. Its hashes depend on the page layout and machine: when a change moves the page, record it with `UPDATE_GOLDEN=1` on the unchanged code first, then compare. Output goes to `test-results/` (git-ignored).
- Source imports use explicit `.ts` extensions (`allowImportingTsExtensions`), required so Node can run them directly. Keep this in new imports.
- `tsconfig` only includes `src/`; tests are not type-checked by `npm run build`.
- CI (`.github/workflows/static.yml`) runs `npm test` and `npm run build` on push to `main`, then deploys `dist/` to GitHub Pages (the repository's Pages source must be **GitHub Actions**). Vite `base: "./"` keeps asset paths relative, so the build works under `/TowerDefense/`; asset URLs must not be root-absolute.

## Architecture

**Performance experiment.** Defend waves currently contain exactly `500 * wave` enemies (bosses included, hatched brood extra), released over five seconds. `src/defend/performance.ts` logs per-wave FPS, frame p95, update/draw timings and peak enemies every five seconds and on completion/loss/abandon; the latest 100 rows are available at `window.defendPerformance`. Timings are presentation-only and not saved. Dense crowd separation samples at most 8 enemies per indexed cell deterministically, with exact separation in sparse cells. Grass indexes only cells with blades; large-crowd shadows are cached between simulation ticks at unzoomed scale and invalidated when lighting changes; same-pixel shadows of matching size and light are coalesced at this scale. `tests/defend-performance.mjs` benchmarks spawn and city crowds using the full renderer (rain, night, effects on), isolated from player saves. `PERF_SCENE=city`, `PERF_WAVE=20`, `PERF_REALTIME=1`, `PERF_LABEL=name` `PERF_MIX=1` and `PERF_PROFILE=1` select scene, count, wall-clock stepping, output name, mixed enemy kinds and CPU profiling. `PERF_FRAMES` sets the sample length (default 150 frames, first 30 warm up). Defaults run all 20 counts with a fixed 1/60-second update per frame for comparable work; real-time mode is necessary to assess actual pacing. JSON, screenshot and optional CPU profile go to ignored `test-results/`. Replay fixtures include explicit mixed sieges and a quiet repair interval so the stress opening does not remove late-enemy/repair coverage.

**Shell.** `main.ts` builds the shell (`ui/shell.ts`: the currency bar of copper, silver, Gold, Knowledge and upgrade points, with two locked slots kept for resources still to come, the pages and the tab row: Defend, Mine, Library, Upgrades, Settings), loads the save, owns the current tab and `navigate()`, runs the requestAnimationFrame loop (the Mine's and the Library's work on every tab, Defend's and the Mine's frames, the Upgrades page's particles, and a once-a-second tick that settles the Smithy's upgrades against the mine's smiths), and passes pages an `AppContext` (`ui/app.ts`). It also creates the `DefendPage` with its `DefendHost`: the Defend save slice, the wallet (copper, silver and Gold; Unlimited money spends nothing), `bonuses()`, and `earnKills`/`earnWave`, which pay through `progression.ts`. The Settings page's dev options (`ui/settings-page.ts`, rows in `SETTINGS`) sit under ALL ON: Unlimited money (`devMode`: ∞ everywhere, every purchase free), All towers unlocked (`devTowers`: `unlockAllTowers` gives one of every structure when turned on), Instantaneous research (`instantResearch`: a Smithy rank completes at once, smith or none) and All research unlocked, one per Upgrades tab (`devSmithy`, `devCommand`, `devStewardship`, `devMine`, `devLibrary`, `DEV_RESEARCH`: while on, `skillRank`/`trainingRank` count every rank of it as bought; the save's ranks are untouched). Add 1 hour of idle time (`addIdle`) gives the Mine (`MinePage.addAway`: the tick-by-tick catch-up, up to `SIM_AWAY_MS` owed, the rest at the smithy's pace) and the Library (`LibraryPage.addAway`: reckoned like time away, an hour at a time, so it may burn down) that time, moves the Smithy's clock back, and shows the welcome-back screen with what it made. `defendDebug(seconds, weather?)` in the console fast-forwards a battle, `mineDebug(minutes, hire?, weather?)` the mine (forcing the weather), `mineLevel(id, level?)` sets a mine building's level (or, with none, upgrades it for free, rebuild and all), `mineLook(building, zoom?)` zooms in on a mine building and picks it, and `libraryDebug(shelves, librarians, seconds, fire?)` furnishes and runs the library (and sets a table alight).

**Library** is a cathedral nave the player fills, in `src/library/`, saved as `save.library` (null until it first shows); it earns Knowledge, `knowledgeRate` = built shelves × librarians an hour. `geometry.ts` holds where things stand, in pixels (192 × 300, the floor's top at `FLOOR`; a hallway `HALL` long out of each side wall, with `EXITS` at their ends and a water butt in each, `BUTTS`). `sim.ts` (`LibrarySim`): each shelf unit (two rows of seven books) has a plank count in `units` (-1 none, 0 an outline once bought, `PLANKS` built); units stack in ten bays against the back wall in `SHELF_ORDER` up to `SHELF_TOP`, under the stained-glass `WINDOW`. Librarians (2 × 4 pixels, each with a scholarly hat) follow step lists (walk, climb, timed work, `away` beyond a hallway's end): one fetches the wheelbarrow of planks (`barrow`) when building wants planks, and the rest carry planks from it to ladders (one segment a plank, up to the built shelves), outlines and burnt tables; another wheels in the book cart (`bookCart`) of new books when shelves stand empty, which the rest shelve; now and then, the stacks full, one loads the cart with old books and wheels it out for new ones (`booksIn`/`booksOut`); otherwise they sort the stacks (each colour has its bay, `homeBay`, and books are shelved there where there is room; `sorted`), read books, or index them at the tables (every third librarian, who now and then rebinds one in a new colour, `mended`). Each librarian has `energy`, drained by work (`TIRING`) and restored by a cup of tea fetched from outside or, at night, a doze in a free seat; by night (`night`, which the page sets from `daylight`) about half go home down a hallway (`home`) and return by day; now and then two stop to talk (`with`) or one gazes up at the window. After a death the others mourn at the ashes (`remains`), then one sweeps them up and scrubs low soot off the stone (`Fire.scrub`). The two water butts hold `BUTT_FULL` buckets: fire fighters draw from them (and run out to the well when both are dry), those who fled refill them during a fire, and one refills them afterwards. Every book is in a slot, a hand, on a table or in the cart. Once a minute a whole table catches fire with `accidentChance(fireproof)` (1% × 0.9 a rank of Fireproof Wood); `fire.ts` (`Fire`) simulates it on a 2-pixel grid of heat and fuel (rising heat, wet cells, thrown droplets that douse with `fireDrill(fireTraining).douse`). Librarians notice it after a moment, then flee down a hallway or (a share set by Fire Training) fetch buckets from the butts and throw them; heat kills (`deaths`, `remains`). When it is out, `settleFire` removes every shelf left under a quarter (and what stood on it: bought again) and leaves the rest short the planks it lost, for free rebuilding; burnt books, ladders and carts are gone, and `lost` says what it cost. It steps on every tab (the page's `advance`, not while the game is closed) and draws from its own `random(seed)`; `furnish(n)` builds and stocks shelves at once (tests, `libraryDebug`). `render.ts` (`LibraryRenderer`) bakes the nave once (ashlar walls and piers with a height map, doorways, the vault, the floor, the lancet window with its rose in an oak frame and sill, the hallways) and lights it per pixel each frame: ambient and window light by `daylight(now)` (one day and night every `DAY_MS` of wall-clock time) plus the torches, candles and the fire's blazes through the blocks' slopes; it paints outlines, half-built shelves, char and soot, and draws carts, librarians with what they hold, flames, smoke, embers and water over it; the hallways show only where librarians have lately walked. `ui.ts` (`LibraryPage`) is the tab and pays Knowledge on the wall clock; time away (up to `MAX_AWAY_MS`, `src/away.ts`, 24 hours) is reckoned an hour at a time by `idleHours` (`sim.ts`): each hour the library burns down with `idleFireChance(nightWatch)` (50%, 5% less a rank of Night watch, at least 5%; a part hour rolls its share), paying the saved rate for every hour before that, and once burnt it is a new, empty library (an empty one has nothing to burn); the rolls come from the library's seed and its `savedAt`. `awayKnowledge` and `away` (`LibraryAway`: when it burnt and what was lost) are kept for the welcome-back screen. `tests/library.test.ts` covers the stacking, building, carts, the librarians' work, fires and training, the accident rate, Knowledge and the save (including saves from before building, which held a `shelves` count).

**Mine** is the idle side of the game, in `src/mine/`, saved as `save.mine` (null until it first runs). `world.ts` holds the grid (384 × 480 cells, one material each), the world a seed generates (`generate`, `strata`: sky, grass, dirt with rocks, stone with copper, deeper silver and deeper still gold veins, bedrock) and the falling-sand `World.step`: dirt, grass and spoil fall and slide only onto drops of two or more, so slopes settle one across and two up; rocks drop straight; only awake 16 × 16 chunks are stepped. Gravel and loose dirt (pockets in the stone and dirt) slide on any drop and, like falling rock, crush the ladders and timber they land on; lava pools deep down creep slowly and turn to stone where water meets them. A separate `water` layer (one flag a cell) flows down, spreads level and sinks under falling ground. `buildings.ts` lays out the surface buildings either side of the shaft at their levels (`layout(surface, shaftX, levels)`, 1 to `MAX_LEVEL` each, wider each level: the shaft house, the barracks with a lounge and a bay of bunks a level, the warehouse, the forge with two hands' spots a level and the smithy with an anvil a level, `anvils`), each with spots (bunks, stools, stations) and the scripted path to each from the door (`along`, `pathTicks`): a miner inside a building is out of the grid, its feet left at the door. `sim.ts` (`MineSim`) is the operation: a plan grid marks cells to dig or fit (ladder, rail, torch, lamp); the planner sinks the laddered shaft level by level and drives a tunnel out both sides of each; each miner (1 × 2 cells) picks the nearest unclaimed job by a breadth-first search over where it can stand (walk, step up two, climb or put up ladders underground, drop), shores loose ground beside its digs with timber, follows ore it bares, carries ore to the yard by the shaft house (and spoil to the heap) or into a level's cart, which rolls to the shaft, where its load waits (`buckets`) for the hoist: one bucket (`hoist`) let down to each load in turn and wound up to tip it in the `yard`. Forge hands carry the yard's ore into the forge (`fetch`, `CARRY` at a time, gold first) while it holds less than `FORGE_CAP`, so a short-handed forge leaves the backlog in the yard. Each miner has a name for life (`names.ts`, `minerName`: hashed from the seed and the hire, unlike the rest of the crew's) and a trade (`job`: mine, forge, smith) the player sets per miner in the crew list (`setJob`; `setJobs` puts counts to the trades, `jobs` counts them; the second hire goes to the forge and the fifth to the smithy while they have nobody): forge hands smelt the ore piles (`ore`, a `Metals` record of copper, silver and gold, as are packs, carts, the yard and the hoist) into bars (`bars`, `ORE_PER_BAR` ore each) and smiths work the bars, every `BARS_PER_POINT` of a metal making a Smithy point of it, each at a station inside (`stepInside`, `craft`; a trade with nobody works at a quarter pace); fittings and shoring use supplies (`kit`) fetched from the warehouse; at night (`night`) all but the night shift (`nightShift`: 20%, plus 5% a rank of the Coffee skill) sleep in their bunks; hungry miners eat in the lounge; the shaft house keeps a share of the runoff out of the shaft (`seal`: 20%, plus 15% a rank of Waterproofing) and its roof, like every building's, takes the lightning. The sky turns through day and night (`daylight`, one day every `DAY_TICKS`) and spells of `weatherOf` the seed (clear, cloudy, rain, storm; `skyAt` eases between them): rain falls as water that soaks into soil, runs down the shaft and floods the workings, where miners bail it (and douse fires) as jobs; in storms lightning strikes (and can set wood alight) and miners at the surface sit it out in the lounge. Hazards (`hazards`, `struckBy`, `survey`, `stepFire`) can kill a miner by crushing, drowning, starving trapped (`fed`, `MEAL_TICKS`), lava, fire or lightning; `kill` spares the last miner, any death within `DEATH_GAP` of the last (a new mine starts with that grace) and a second death in one catch-up, records the cause in `lost` and the miner in `fallen` (until the player taps it away, `dismiss`, or hires again), and posts `news` the page and renderer show. A prospect's ore is finite (`oreFound`, `oreLeft` as of the last `survey`): once the shaft is at the deepest level and the planned work is done (or has stopped shrinking for five minutes) it is `workedOut`, and `prospectNext(seed)` builds the next prospect, a fresh world, carrying the crew, the stock and the losses (a `MineSave` without `cells` is such a prospect: the crew starts at the barracks). Each building has a level (`buildingLevels`, raised with Gold by `upgrade(id)` at `upgradeCost`, refused by `upgradeBlock`): the barracks bunks `CREW_PER_LEVEL` a level (`crewCap`, which `hire` keeps to), the forge has room for `FORGE_PER_LEVEL` hands and the smithy for `SMITHS_PER_LEVEL` smiths (`jobCap`, which `setJob`/`setJobs` keep to; the forge also holds more ore, `forgeCap`), the shaft house keeps out more rain, and the warehouse holds `STOCK_PER_LEVEL` supplies and brings in `STOCK_RATE` a minute a level (`stock`, `stockCap`, `stockRate`) and lets the others rise one level past it (`maxLevel`). Miners fetch their kit from `stock`, so with none the fittings (and the shaft) wait. An upgrade rebuilds the building and moves any it pushes along (`rebuilds`: taken down at `from`, then raised; shut meanwhile, everyone inside sent out, its trade's hands working the face), using supplies as it goes and waiting when there are none; `setLevel` sets a level at once (tests, the console). Fewer miners make the next hire cheaper (`sim.price`). `collect()` hands over the Smithy points made (into `save.smithy`); `hirePrice` prices miners in Gold. Sinking the shaft and the ladders a climbing miner puts up use supplies too, so with none the shaft waits. Smiths working a Smithy upgrade can't be dragged out of the smithy (the host's `busySmiths`); Master smith makes room for another (`extraSmiths`). The mine uses no shared random stream: generation and choices hash the seed, cells and tick. `art.ts` paints the surface structures as pixel art at two pixels a cell (`paintWall`, `paintBack`, `paintShell`: clapboards, board and batten or ashlar with windows, back walls, posts, doors, tiled, slated or shingled roofs and the forge's brick chimney; `paintHeadframe`, `paintGrave`), each baked once into a canvas by `Sprites` with a copy per step of light. `figures.ts` draws the miners as 2 × 4 half-cell figures (`drawFigure` in a `Pose`: standing, walking, climbing with arms reaching, at work with an arm out, reaching overhead, sitting, crouched; `drawSleeper`, breathing) in an `outfit` picked from each one's name within its trade; `acts.ts` times the crew's movements on the wall clock, presentation only: each miner's `temperament` (two favourite habits from its name), the habit a waiting miner is in (`habitAt`, `habitPose`: looking about, stretching, sitting, whistling, yawning, tapping a foot, sifting the ground), a forge hand's shovel cycle (`shovelAt`) and a smith's strokes on a cooling bar until it is quenched (`hammerAt`); the renderer adds chats between miners waiting side by side, pick and hammer swings, buckets dipped, sweat when hungry, hat lamps' glow, the furnace flaring at each throw, the bellows, the winch drum and the headframe wheel's spokes turning with the hoist; `particles.ts` (`Particles`) moves the effects each its own way (dust and grit fall and settle, chimney smoke and steam rise and drift, sparks arc, z's, wisps and whistled notes float up, embers drift up flickering, drops fall, talk shows as dots). `render.ts` (`MineRenderer`) paints visible rows two pixels a cell each way into an offscreen image (the miners' pixel size), each cell's four pixels given its material's detail (grains, specks, cracks, ore set in stone, grass blades, rungs, rails and sleepers, flames) and a lit lip or shadow where it meets open air, lit by a two-channel light map (daylight, and torches, lamps, lava, fires and miners) spread cell to cell and blended between cells per pixel (unlit cells take a fast path), and repainted for the world's changes at most every 60 ms, under a pan/zoom camera (an even number of device pixels a cell, so each pixel is whole and they meet without seams; zoom 1 shows `VIEW_CELLS` across the view, in to `MAX_ZOOM`; `target` follows one miner) with stars by night, clouds, rain and lightning, the headframe, the buildings (each front wall fading while anyone is inside, to show the bunks, lounge, shelves, furnace and ore piles, anvil and bars, and the miners sleeping or at work; the shaft house's lantern and the barracks' windows lit at night), graves for lost miners, carts, the hoist's rope and bucket (eased between steps), the yard's ore, the forge's heap and shelves filling toward `FORGE_CAP`, the miners and the effects over it (from `stream("effects")`), with half cells snapped to whole screen pixels (`fine`); a building tapped (`picked`, `buildingAt`) is outlined and shown open. `ui.ts` (`MinePage`) is the tab: drag pans, the wheel and a pinch zoom; a tapped building shows its stats, level and upgrade button (or how its rebuild goes); the Crew button slides the crew list in beside the view (names dragged between the trades' boxes, each showing its room, tapped to follow; the renderer's `refWidth` keeps the zoom while the view narrows); a tap on a building shows its stats over the view (bunks, ore in the forge, bars waiting, the hoist); New Prospect moves on (asking first unless the prospect is worked out); and `advance(now)` runs the sim on the wall clock within a frame budget, catching up up to `SIM_AWAY_MS` (two hours) of time away after loading tick by tick; time away past that, up to `MAX_AWAY_MS` (24 hours), is paid at once at the smithy's `pace` (the sim's Smithy points an hour, each minute's bars worked eased in over `PACE_MINUTES`, saved as `pace`), and `away` (`MineAway`) keeps the account for the welcome-back screen, the catch-up's points and losses added as it runs. `tests/mine.test.ts` covers the physics (water, gravel, lava, fire), generation, the crew's work and pay, the buildings, trades, night shift, supplies and waterproofing, weather, floods, deaths and their spacing, names and the lost, prospects, the hoist and the yard, building levels, caps, supplies and rebuilds, and the save; `tests/mine-particles.test.ts` how each effect moves; `tests/mine-acts.test.ts` the temperaments, habits, shovel and hammer cycles.

**Defend** is the game, self-contained in `src/defend/` with its own save slice (`save.defend`) and page (`DefendPage`, `defend/ui.ts`); see `docs/DEFEND.md`. Its battle simulation, `DefendSim` (`defend/sim.ts`), owns the world state and what happens to it (damage, rebuilding, blasts, movement), and steps the units in a fixed order. Each unit type's decisions live in its own module: `enemies.ts`, `troops.ts` (barracks, swordsmen, archers; the Mage Guild trains its fire mages and the Valkyrie palace its valkyries the same way), `mages.ts` (fire mages throwing `sim.fireballs`, which burst through `sim.explode` sparing your own people and leave `sim.blazes`, burning ground that hurts ground enemies a second; a burn passes `hurtEnemy(e, n, false)` so it doesn't flash), `valkyries.ts` (valkyries making charge stabs: a blink along the line toward an enemy, as far as `stabLength` or until `blocked` by something solid, hurting every enemy within `STAB_WIDTH` of it, leaving `sim.stabs` and an optional `guard` on the soldier during which neither enemies nor blasts hurt her, absent when unset), `dark-wizards.ts` (the dark wizard keep's four corner turrets, `DarkKeeps`, at `turretSpots`, and its one dark wizard, `stepDarkWizard`, both loosing black lightning through `chainBolt`: a bolt strikes its target, then leaps to the nearest enemy not yet struck within `chainJump`, forking back from the latest struck that still has one, up to `turretChain`/`wizardChain` enemies; `sim.bolts` keeps each bolt's points and `from` links), `siege.ts` (the self-driving siege engines, rolling cannons, ballistas, firework launchers, trebuchets, great bombards and dragonfire batteries, each an `EnemyDef` with a `siege` entry: an engine marches like any enemy and, with the keep or the building its own flow-field way runs into (`blockerAhead`) or a defender within range, braces (`SIEGE_SETUP`) and shoots `sim.siegeShots`, balls, stones, piercing bolts or rocket volleys that hurt only the city and its people; `aim` is absent while it rolls, `siegeShots` hashes in replays only when present), `boats.ts` (the magic boats, Enchanted Skiff, Spellbound Sloop, Arcane Galleon and Deluge Ark, each an `EnemyDef` with a `boat` entry: a boat sails straight at the keep through the ground (`stepBoat`), dropping pools of its water (`sim.floods`, each holding then drying by `floodRadius`, found through a per-tile index by `wetAt`) whose reach sinks every house and structure (`sim.sink`, recorded in `sim.sinkings` for the art; the galleon also sinks wall stones, the ark the keep) and ramming what it can't sink; `stepFloods` soaks fire mages and puts out blazes, `fizzles` stops blasts centred in water (`explode`, `hostileBurst`, fireballs) and `sheltered` spares whoever stands in it from splash and fire; both lists are empty in runs without boats, and `ageWater` dries them after a loss), `boat-art.ts` (the boats as outlined pixel sprites per heading, foam and rune light), `flood-art.ts` (`FloodArt`: the water as pond-style pixel art with the bank mirrored in, rings, crests and sparkles, walls rising out of it, buildings sinking into it), `siege-art.ts` (the engines as outlined pixel sprites at `SP` pixels a cell, one cached sprite per aim direction and frame, their shots and the rockets' `firework` effects), `war-banner.ts` (`WarBanner`, `sim.warBanner`, set by `plantBanner`: the item the player plants mid-battle; while it stands, every troop's step hands over to `answerBanner` when nothing is in its own reach, marching down the banner's flow field (`fillFlowField`, standing buildings at a high cost) and closing on enemies within `RALLY_REACH` of it; null in every run without one, so replays are untouched; the page's drag is `{ from: "banner", placed? }`, whose `Drop` says whether a planted banner was tapped, and the renderer draws it with `drawWarBanner`, the keep's `flagPixels`), `civilians.ts`, `towers.ts` and `wizard.ts` (wizard towers alternating `sim.flames` and `sim.frosts`; an enemy's optional `chill` slows it, and stays absent when unset so runs without ice hash exactly as before). `pathing.ts` holds the pure grid A*, the enemies' flow field and the collision test. A sim takes the Armory's levels and, optionally, `Bonuses` (`catalog.ts`: multipliers on troop HP and damage, drill time, tower damage and reload, wall and keep HP, rebuild time and bomb damage; `NO_BONUSES` is all 1, so a sim without them plays exactly as before), and counts the enemies slain by kind (`sim.slain`, which the page pays for each frame; not part of the replayed state). `DefendRenderer` (`defend/render.ts`) owns the camera and the order of the drawing passes: `city-layer.ts` paints the cached static city, with the streets as dirt pixel art (`ground-art.ts`, `groundArt`: blotchy browns darker at the kerbs, grass growing out unevenly over the edges beside parks and bare dirt biting back into them, `bare` marking those park pixels so the live grass keeps off) and the shadows (`shadow-art.ts`: `heights` stands houses up as gabled roofs, the wall taller with its sloping face, the keep, structures and tree canopies, and `shadowMask` casts one crisp mask from the upper left over it, so the wall's shadow falls on the roofs beside it; fallen buildings cast nothing); it re-exports the pond and tree geometry of `park-geometry.ts`, `pondDisc`/`pondPath`/`POND`, `hasTree`/`treeCanopy`, that the live effects line up with. Then **park life** over it (`park-art.ts`, `parkArt`: the ponds and trees as pixel art at 8 pixels a cell, baked once per city with the open-water mask everything on the water keeps to, its geometry from `park-geometry.ts`; the trees are separate sprites (`trees`, and all of them in `canopies` for the ponds' reflections) that `park-trees.ts` (`ParkTrees`) draws after the units, each fading to half opacity while anyone is under it and darkened by the battle's light; `pond-water.ts`, `PondWater`: faint pixel rain rings all over the water while it rains, and the bank mirrored into the water from the city layer in strips shifted by the shimmer and the rings, tinted and masked to the open water; `pond-ducks.ts`, `Ducks`: a few pixel ducks at 16 pixels a cell (half the parks' art scale) when it isn't raining, with drift, paddle, dabble, preen, follow, flee and sleep states and rare wake rings; `park-grass.ts`, `ParkGrass`: blades planned per park cell clear of canopies and shores, swaying with the wind and gusts, parting around the walkers the renderer passes, written into one pixel buffer at 8 pixels a cell and rebuilt at most 30 times a second; both skipped when the `effectsOff` setting is on), `fences.ts`, `lighting.ts` the torchlight and shadows, `ground-relief.ts` (`GroundRelief`: the flagstones' bump map outside the city, four facing masks baked from the floor art's brightness by `paintFloor` in `city-layer.ts`, lit per light through cached weight sprites; fixed lights baked per map version, moving ones per frame), `battle-art.ts` each frame's damage, scorches, units and effects (a swordsman's strike drawn as a half-circle sword swing with a lunge and a fading trail, timed from its cooldown so the sim state is untouched), `dark-art.ts` (the dark wizard's sprite and staff, `drawDarkWizard`; black lightning rasterized into one board-sized pixel buffer, `BoltBuffer`/`rasterBolts`, black cores in crimson glow, only the changed box cleared and copied, drawn by `DarkArt` once a frame; `darkLights`), `valkyrie-art.ts` (the valkyries as cached sprites with their spears and guard halo, `drawValkyrie`; the charge's streak, after-images, tip star, landing ring and hit sparks, `drawStabs`; `stabLights`), `mage-art.ts` (the fire mages as crisp cached sprites, `drawMage`; fireballs and their trails, `drawFireballs`; the blazes' scorch, embers and pixel flame tongues, `drawBlazes`, all hashed from battle time and each blaze's seed; `mageLights` lights the streets round them), `wizard-art.ts` (`WizardArt`: the wizard towers' fire particles and the ice wave's shaded crystal shards, advanced on battle time; `flameLights` turns each flame into carried and relief lights), `edit-overlay.ts` the building grid and drag overlay, `roof-art.ts` the houses' roofs (`roofPixels`: pixel art at 8 pixels a cell inside the black outline, shingle courses with per-shingle shading, seeded per lot by `roofSeed` with wear, moss, missing and patched shingles and the odd chimney; `roofSprite` caches the canvases; `tests/defend-roof-art.test.ts`), and `structure-art.ts` the building art, banner and palette icons (the keep, `keepPixels(stage)`, with a damage stage per 20% of HP lost from `keepStage` and `keepRubblePixels` once fallen, and its waving banner, `flagPixels`, are pixel art at 8 pixels a cell like the parks; `tests/defend-keep-art.test.ts`). The other structures are pixel art too (`tower-art.ts`, `structurePixels(kind, cw, ch, stage, seed)` and `structureRubblePixels`), and every building but the keep shows `damageStage` (below 75%, 50% and 25% of HP) and rubble once fallen through `damage-art.ts` (`damage`, `rubblePixels`, the wall stones' `wallDamagePixels`/`wallRubblePixels`, and the cached `sprite`s), seeded by its lot; houses through `roof-art.ts`'s `houseDamagePixels`/`houseRubblePixels`. The city layer repaints when any building's stage changes (`damageKey`); `tests/defend-damage-art.test.ts`. When a run ends (`DrawOptions.over`), the renderer douses the lights in a wave out from the keep (`DefendLighting.burning`, and the `Burning` passed to the units' hand torches). Park life is presentation only: it never changes the city or the battle, and draws its randomness (rain rings) from `defendRandom("effects")`. All units draw from one seeded random stream, so the step order and each unit's draws decide a replay. `tests/defend-replay.test.ts` steps fixed cities, upgrade levels, seeds, bombs and demolitions through `update()` and hashes the whole sim state every 5 s against `tests/fixtures/defend-replay.golden.json`, reporting when a run first diverges. Regenerate it with `UPDATE_GOLDEN=1` only for an intended gameplay change. The battle must play the same in every JavaScript engine and Node version (CI runs Node 24), so battle code uses only `+ - * /` and `Math.sqrt`, with `intPow`, `sq` and `dist` from `src/exact.ts`: no `Math.pow`/`**`, `hypot`, `exp`, `log` or trigonometry (the wizard aims by unit vectors and tests cones by slope). Drawing may use `Math` freely. Check a replay change under both: `npx -y node@24 --experimental-transform-types --import ./tests/pin-random.ts --test tests/defend-replay.test.ts`. On the page, the board's canvas fills its view and the palette (`☰ Build`, in battle `☰ Items`) slides in beside it; `DefendRenderer.resize(refW, refH)` takes the board's scale from the whole stage, so it holds while the view narrows (`boardSize(px)` in `grid.ts` is the board's extent in canvas pixels, which board-space passes use rather than the canvas's size), and the camera centres the board along an edge where the view is wider. Board pointers go through `board-pointers.ts` (`BoardPointers`), a small state machine: idle, viewing (one pointer pans, two pinch-zoom), or dragging a palette item, structure, keep, city tile or bomb under a ghost icon. It only turns pointers into board cells; each drag is an `EditSession` (`edit-session.ts`), a pure transaction over the layout it started from: what a press lifts (`EditSession.lift`), the legal tiles and the layout each makes, the overlay shown while held, and the `Drop` a release makes, which the page applies. `tests/defend-edit-session.test.ts` drives whole drags in Node. `drag-rules.ts` holds the rules behind it (unit-tested in `tests/defend-drag-rules.test.ts`). The city itself comes from `layout.ts` (the player's tiles and structures; `fitLayout` picks each structure's cells: every structure takes a tile share, `size` in sixteenths in `catalog.ts`, `TILE_ROOM` a tile, with a smaller `compact` footprint behind a building-specific upgrade that the layout's `compact` kinds name; a tile's structures are fitted together, biggest first, each in a random spot seeded by its saved `spot`, retried until they all fit; dropping anything on a tile reshuffles every `spot` there from the layout's `rolls`; a structure with `span` 2, the dark wizard keep, fills a 2 × 2 block of tiles from its saved top left tile, taking all of each (`blockTiles`, `covers`, `spanOf`), and an `EditSession` carries it by the block centred nearest the pointer, its overlay's `span` framing the whole block) and `citygen.ts` (streets, parks, houses, ponds and wall stones, as a pipeline of stages). `tests/defend-city.test.ts` hashes seeded random walks of layout edits, their fits and failure reasons, and the cities generated along the way against `tests/fixtures/defend-city.golden.json`; regenerate it with `UPDATE_GOLDEN=1` only for an intended change to city building. `fences.ts` lays decorative fences along the street sides of parks and snaps them into splinters under walking enemies and blasts, and `progress.ts` holds the saved Defend state, its purchases, and `decodeDefendSave`, which rebuilds the saved layout piece by piece and drops it unless it is well formed and owned; one that no longer fits is reshuffled and failing that has its newest structures returned to the palette (`sized`, which buying a compact upgrade also runs; `compactKinds` reads the layout's `compact` from the levels, so it isn't saved on its own). `tests/defend-fences-save.test.ts` hashes fence sections, seeded fence runs and `decodeDefendSave` over a corpus of saves against `tests/fixtures/defend-fences-save.golden.json`. `tests/defend-shadows.test.ts` checks the shadow casting, the street edges and the trees' fade. `tests/defend-park-life.test.ts` checks where grass is planned, the pixel ponds' open water, and the ducks keeping to it, fleeing walkers and sleeping at night, and `tests/defend-wizard.test.ts` the wizard tower's turns, cone and chill; `tests/defend.test.ts` covers tile shares, random spots, old saves and the valkyries' charge.

**Welcome back.** `src/away.ts` holds `MAX_AWAY_MS` (24 hours, the cap on paid time away) and `span` (time in words). `ui/welcome.ts` (`WelcomeBack`) shows, on opening the game after `WELCOME_MS` or more away with something earned, the shared parchment dialog with the time away, the Library's Knowledge and the Mine's Smithy points by metal on nailed oak boards, refreshed each frame while the Mine still catches up (and whether the library burnt down while away, and what it lost); `main.ts` measures the time away from the Mine's and the Library's `savedAt` before loading them. The rewards are paid whether or not it shows.

**Progression** (`src/progression.ts`, pure functions over the save): the Smithy's upgrades (called Training in code: the `TRAINING` rows, `save.training`, `trainingJobs`), each rank `per` percent on its target up to `max` ranks, costing one Smithy point (`rankPrice`: copper for a row's first ten ranks, silver to 25, gold after) from `save.smithy`, which the mine's smithy fills; a rank in work (`startTraining`, `addSmith`, `removeSmith`, `cancelTraining` with its point returned) is worked by the mine's smiths by name (`busySmiths`), each smith adding a share, so `trainingLeft` divides by their number; `settleTraining(save, now, smiths)` works them on from `trainingClock` and drops smiths no longer at the smithy (an upgrade with none waits); durations in `training-jobs.ts` (60 s of one smith for a row's first rank, each after 50% longer). Upgrade points (`save.upgradePoints`, one for each new best wave, banked for later). The skill trees' purchases (`skillPurchase`, `buySkill`), and what a defense pays (`payKills`: `KILL_GOLD`; `payWave`: `waveGold`, copper, silver on boss waves, Knowledge and an upgrade point past the best wave). `multiplier(save, target)` adds the Smithy's and the skills' percents for a target (a time's percent divides, `smithing` among them), and `bonuses(save)` folds them into the battle's `Bonuses`; `gold` multiplies the rewards. `src/skill-trees.ts` defines the skills (`SKILLS`: name, glyph, max ranks, Knowledge `base` with `skillCost = base × (rank + 1)`, effect) and the `TREES` (Command, Stewardship; Mine: Coffee and Waterproofing, read as ranks by the mine; Library: Fireproof Wood, Fire Training and Night watch, read as ranks by the library) with node positions and requirements; `ui/skill-tree-page.ts` (`SkillTreePage`) draws the Smithy tab (asking before the last smith comes off a rank) and the trees (pan and zoom with `ui/pan-zoom.ts`, particles from `tree-particles.ts` and `training-particles.ts`). `tests/progression.test.ts` covers it.

**Sound and flourishes.** `src/sound.ts` makes every sound in code with Web Audio (no sound files): `play(cue)` builds each `Cue` (the oak buttons' `knock`, the tab row's `stone`, `coin` for spending, `chime`/`unlock` for skills, `wave`, `record`, `levelUp` (an upgrade point), `trained` (a Smithy upgrade done), the boss wave's `horn`, the fallen keep's `fallen`) from noise bursts, oscillators and bell partials, into a generated stone-hall echo, and stays silent with the `soundOff` setting. `src/ui/flourish.ts` draws the DOM celebrations: `sparks` (embers off a pressed button, gold for a win, arcane for an upgrade point) and `replay` (restarts a CSS animation class); none play under Reduce motion. `main.ts` knocks and sparks on every button click, glints a rising currency and plays the upgrade point and Smithy cues; the Defend page and skill trees play their own. The animations themselves are in `theme.css`'s Motion section, off when the root has `.reduce-motion` (set from the setting) or the system prefers reduced motion. Both draw from `stream("effects")`.

**Torch light toolkit.** `src/lighting.ts` (the candle colour ramp, flicker and sway: `getTorchFlicker`, `getTorchSway`, `LIGHTING_CONFIG`), `src/torch-light.ts` (`lightFalloff`, `glowColor`, and the occlusion-aware baked glow `torchLightField`/`bakeTorchLight`) and `src/visibility.ts` (`Torch`, `TORCH_LIGHT`, `computeVisibilityPolygon`, `insidePolygon`) are kept from the dungeon game for Defend and future use; `defend/lighting.ts` builds the city's lights on them.

**Randomness.** Defend's city, battle and weather rolls come from `defendRandom("rolls")` and its effects (splinters, rain, ripples) from `defendRandom("effects")` (`defend/grid.ts`); the shell's visual effects from `stream("effects")` (`src/random.ts`). Each seeds itself once at start-up from `Math.random` and its name (unless a test pinned it); nothing else calls `Math.random` (`tests/random-streams.test.ts`). A new mine's seed comes from `stream("game")`.

**Saves.** `src/save.ts` loads defensively: `defaults()` defines every field and `decode()` keeps only what is well formed (a newer version starts afresh; Knowledge was once `valor`, copper and silver were `ironBar` and `steelBar`, which `decode()` still reads; a save from before upgrade points gets one for each wave of its best, and a rank in training from before the Smithy counts as done). When adding save state, add it to `defaults()`, the `Save` type and `decode()`. The mine's grid and plan are stored run-length encoded as base64 (`encodeGrid`/`decodeGrid`), as is its water layer (optional, so older saves load dry), and `decodeMineSave` drops a mine unless it is whole (its burning cells, losses, mercy, miners' meals, names, trades and supplies, the allocation, the forge's and smithy's stock (old saves' iron reads as copper), the prospect, the lost, `workedOut`, the building levels, supplies and rebuilds are checked when present, and a mine saved before levels gets levels with room for its crew and trades; a mine saved before the world was widened, 128 cells across, keeps its crew and stock and starts a fresh prospect of its seed); the library's book slots use the same encoding (`decodeLibrarySave`). Player settings are one row each in `SETTINGS` (`src/settings.ts`), from which the `Settings` type, defaults and decoder come; `tests/settings.test.ts` checks every row round-trips.

## Conventions

- Keep this file current. When a change adds, renames, or removes modules, alters architecture, changes commands/scripts or test setup, or changes save rules, update AGENTS.md in the same change, and keep the README's "How it's built" accurate. `CLAUDE.md` only imports this file; don't add content there.
- `CONTEXT.md` is the domain glossary (terms only, no implementation). Use its words in code, comments and docs, and add a term there when a change names a new domain concept.
- All text uses the bundled Cinzel font (`assets/fonts/Cinzel/`); no remote fonts.
- The page's look lives in `src/theme.css`, loaded after `src/style.css` (layout): dressed stone for the hall and tabs, oak boards nailed at the corners for buttons and panels, brass trim and an ember glow for chosen and leading buttons, red lacquer for danger, parchment for dialogs, banners, the Defend settings and tooltips, and an alchemical circle behind the skill trees. Its textures are small tiling SVGs in `assets/theme/` (`stone`, `wood`, `parchment`, `sigil`, `rule`, `seal`, and `frame`, the board's iron corner brackets). Style new UI from its tokens (`--wood`, `--stone`, `--parchment`, `--nails`, `--brass-nails`, `--ink`) rather than flat colours.
- Goldens (`tests/fixtures/*.golden.json`) pin current output; an intended change to city generation, the battle, fences or saves fails them until re-recorded with `UPDATE_GOLDEN=1`. Re-record as part of that change and say which and why in the commit message. A refactor re-records nothing.
- Run the area's tests while iterating (`tests/defend*.test.ts` for Defend, `tests/mine.test.ts` for the Mine, `tests/library.test.ts` for the Library, `tests/progression.test.ts tests/settings.test.ts` for progression and saves), then `npm test` and `npm run build` before committing.
